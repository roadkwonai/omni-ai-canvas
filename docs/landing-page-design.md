# Omni AI Canvas 랜딩 페이지 기획·설계

> 로고·부제·마스코트는 [브랜드 규칙](brand.md)을 따른다. [개편 제안](landing-redesign-proposal.md)의 1~2단계를 2026-11-24에 구현했다. 대사 구간과 다섯째 탭(3단계), 형식 묶음과 바로 시작(4단계)은 남아 있으며 [기능 소개 보강 제안](landing-features-proposal.md)에서 범위를 넓혔다.

## 제품과 방문자

단편 드라마, 숏폼, 광고 또는 공모전 출품작을 직접 만드는 제작자가 대상이다. 방문자는 초안, 생성 결과, 편집 파일을 오갈 때 원본과 선택 근거를 놓치기 쉽다. Omni AI Canvas는 대본과 참조, 연출 후보, 채택 테이크를 같은 보드에 연결한다. 페이지의 주요 행동은 **캔버스 열기**다.

## 참고 사례 검토

[Omni AI Trading 랜딩](https://roadkwonai.github.io/omni-ai-trading/)과 로컬 랜딩 소스를 함께 확인했다. 아래 배치와 상호작용을 Omni AI Canvas의 제작 시나리오에 맞췄다.

| 참고한 방식 | 캔버스에 적용한 결정 |
| --- | --- |
| 첫 화면에서 사용 대상과 결과를 말하고 실제 화면을 증거로 붙인다. | “대본 한 줄이 영상 한 편이 돼요” 아래에 부제를 두고 예제 결과 영상과 그 컷을 만든 자료를 한 틀에 놓는다. |
| 긴 페이지의 앞에서 중요한 기능으로 바로 이동할 수 있다. | 제작 과정, 제작 형식, 기능, 사용 가이드를 상단에서 연다. |
| 화면 갤러리에서 무엇을 하고 무슨 결과가 남는지 캡션으로 설명한다. | 같은 예제 작품의 보드, 감정 편집기, 타임라인, 5초 결과 예제를 네 탭으로 잇는다. 이미지는 원본 크기로 열 수 있다. |
| 짧은 모션으로 설명의 차례를 잡고 모션 줄이기를 따른다. | 첫 화면과 핵심 문장만 움직인다. 키보드와 모션 줄이기에서도 모든 안내와 제어를 쓸 수 있다. |

첨부된 Pro Kit README의 중앙 이미지, 제목·한 줄 소개·기술 배지·바로가기 목차 형식을 적용했다. 제품 서술의 근거는 [README](../README.md)와 [전체 사용 가이드](user-guide.md)다.

## 스크롤 시나리오

| 순서 | 방문자가 확인하는 내용 | 화면 구성 |
| --- | --- | --- |
| 1. 첫 화면 | 무엇을 하는 곳인지와 결과를 본다. | 제목, 부제, 예제 결과 영상, 컷을 만든 자료 네 칸. 사실 세 줄 |
| 2. 소개 영상 | 5분 동안 전체 흐름을 본다. | 누르면 재생하는 YouTube 영상과 장면 10곳. 누르기 전에는 YouTube에 연결하지 않는다. 넓은 화면은 오른쪽, 767px 이하는 아래 두 열 목록 |
| 3. 문제와 구조 | 왜 보드가 필요한지 안다. | 불편 세 가지와 여러 모델 인포그래픽. 767px 이하에서는 불편 세 가지만 |
| 4. 한 장면의 제작 과정 | 무엇을 연결하고, 어떤 연출을 비교하고, 채택한 컷을 어떻게 쓰는지 확인한다. | 〈마지막 상영〉의 **자료 연결 → 이미지 연출 → 컷 편집 → 예제 재생** 탭. 첫 화면의 자료에서 바로 열린다 |
| 5. 연출 | 어떻게 찍을지 예제로 비교한다. | 카메라 이동 영상과 구도·배치·렌즈·시점의 실사 사진. 카메라 이동은 로컬 보관함의 영상을 먼저 쓰고 없으면 직접 만든 영상을 쓴다 |
| 6. 핵심 문장 | 무엇이 남는지 기억한다. | 제작 과정에 이어지는 한 문장 |
| 7. 제작 형식 | 내 작품의 출발점을 찾는다. | 기본 형식 10개. 무형식과 보드 프리셋은 별도 시작 방식 |
| 8. 도구 | 막히는 곳에서 무엇을 쓸지 안다. | 다섯 도구. 이미지 연출과 타임라인은 실제 화면. 나머지는 한 문장과 가이드 |
| 9. 비용과 보관 | 언제 사용량이 드는지, 자료가 어디 남는지 안다. | 작업별 실행 경로 도표와 네 가지 답 |
| 10. 시작 준비 | 남은 질문을 풀고 연다. | FAQ 4개, 오미와 캔버스 열기 |

## 화면과 검증 기준

Elaya의 콘텐츠 구성과 Hallmark의 실제 제품 증거, SEED의 의미 기반 토큰을 적용한다. 자체 호스팅 Pretendard Variable, 짙은 영사실 표면, 따뜻한 종이색, 당근색의 주요 행동을 사용한다. 한국어 제목은 의미 단위로 끊는다. 320px과 390px에서는 장면 자료와 텍스트가 한 열로 이어지고, 탭은 두 열로 배치한다. 첫 화면에서 주요 버튼과 예제 증거를 확인한다. 검색 색인 제외는 로컬 전용 운영 범위를 따른다.
