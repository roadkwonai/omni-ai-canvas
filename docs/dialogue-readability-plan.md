# 여러 화자 대화 가독성 개선

상태: 안 B의 1~3단계를 2026-11-24에 구현했다. 관련 설계는 [대본 TTS와 캐릭터 목소리 제작](tts-studio-design.md)의 여러 화자 대화다.

## 지금 화면의 문제

실제 대본(23줄, 화자 4명)과 검증용 대본(6줄, 화자 4명)을 1440px·320px에서 보고 정리했다.

| 문제 | 근거 |
| --- | --- |
| 누가 말하는지 훑어보기 어렵다 | 입력창의 화자, 지시, 대사가 같은 색과 굵기다. |
| 지시가 대사를 가린다 | `[calm documentary narration] [속마음]`처럼 영어 지시가 대사보다 길어진다. |
| 대사와 목소리 설정이 이어지지 않는다 | 화자 카드가 대화 아래에 따로 있어 같은 인물임을 이름으로만 찾는다. |
| 편집과 결과가 나뉜다 | 들어 보고 고치려면 맨 아래 결과와 맨 위 입력창을 오간다. 어느 줄을 다시 만들어야 하는지도 보이지 않는다. |
| 지시 버튼이 자리를 많이 차지한다 | 버튼 33개가 대화와 화자 설정 사이 약 260px를 쓴다. |
| 이름을 다르게 쓰면 화자가 늘어난다 | `시우`와 `강시우`가 다른 화자가 되지만 화자 수로만 드러난다. |

## 비교한 안

| 안 | 장점 | 한계 | 판단 |
| --- | --- | --- | --- |
| A. 색을 입힌 글 | 지금의 입력창을 유지하고 구현이 작다. | 줄별 듣기·다시 만들기를 붙일 자리가 없고, 영어 지시를 한국어로 바꿔 보여주면 글자 위치가 어긋난다. | 보류 |
| B. 대본형 줄 | 화자, 지시, 대사, 상태, 줄별 작업을 한 줄에서 읽고 고친다. 좁은 화면에서도 순서가 유지된다. | 줄 편집기를 새로 만들어야 한다. | **추천** |
| C. 말풍선 | 두 사람의 대화가 직관적이다. | 세 명부터 좌우 구분이 뜻을 잃고, 320px에서 글 폭이 좁다. 줄별 작업을 놓기 어렵다. | 제외 |

## 설계(안 B)

- **화자 태그**: 화자마다 SEED 팔레트의 연한 배경(100)과 진한 글자(900)를 쓴다. 파랑·초록·보라·노랑·빨강·주황·분홍·청록 8색이며 실화면에서 잰 글자 대비는 7.7:1 이상이다. 색은 등장 순서로 정하고 프로젝트별로 화자 이름에 저장한다. 색만으로 구분하지 않도록 이름을 항상 표시한다. 빨강은 오류 표시와 겹치지 않게 일곱 번째 이후에만 쓴다.
- **줄**: 화자 태그, 지시 태그, 대사, 상태(새 줄·고침·완성·실패), 듣기와 다시 만들기를 한 줄에 둔다. 320px에서는 화자 태그와 작업 버튼이 첫 줄, 대사가 둘째 줄이다.
- **지시 태그**: 화면에는 `한숨`, `속삭임` 같은 한국어를 보여주고 저장과 합성에는 지금의 지시를 쓴다. 감싸는 지시는 밑줄과 태그로 범위를 보여준다. 한국어로 적은 `[한숨]`도 같은 지시로 읽는다.
- **줄 편집**: 줄을 누르면 그 자리에서 글로 고친다. 화자는 목록에서 바꾼다. Enter로 저장하고, Ctrl·⌘+Enter로 저장한 뒤 다음 줄을 만들고, Esc로 취소한다. 줄에서 Alt+위·아래로 순서를 바꾼다. 전체를 붙여 넣거나 한꺼번에 고칠 때는 **글로 편집**으로 지금의 입력창을 연다.
- **화자 줄**: 화자별 목소리 카드를 대화 위로 올리고 같은 색 태그를 쓴다. 화자를 누르면 그 인물의 줄만 강조한다. 성을 빼거나 띄어 쓴 것만 다른 이름은 합칠지 묻는다.
- **지시 넣기**: 버튼 33개를 고른 줄에서 여는 작은 목록으로 옮긴다. AI가 넣은 지시는 태그 모양으로 구분하고, 이유와 되돌리기는 그 줄에서 연다. 지금의 별도 목록은 없앤다.
- **결과**: 만든 뒤에는 같은 줄에서 듣는다. 재생 중인 줄을 강조하고, 고친 줄 수를 **바뀐 3줄 만들기** 버튼에 보여준다.

## 단계

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 화자 색 태그, 줄 보기, 한국어 지시 태그, 글로 편집 전환 | 같은 대본을 글과 줄로 오가도 내용이 같다. 8색의 글자 대비가 4.5:1 이상이다. |
| 2 | 줄 편집, 줄 상태, 줄에서 듣기·다시 만들기, 재생 줄 강조 | 결과 목록 없이 줄에서 모든 작업을 한다. 고친 줄만 다시 만든다. |
| 3 | 화자 줄과 강조, 지시 목록, AI 이유·되돌리기를 줄로 이동, 비슷한 이름 합치기 | 세로 길이가 지금보다 줄고 33개 버튼이 사라진다. |

각 단계에서 글과 줄의 왕복 변환, 한국어·영어 지시의 왕복 변환을 먼저 테스트로 쓴다. 120줄·8명에서 입력 지연, 키보드 이동과 초점 복귀, 화면 낭독기의 줄 읽기 순서, 1440px·390px·320px의 넘침을 확인한다.

## 검증 결과

1440px·390px·320px에서 가로 넘침이 없고 버튼은 36px 이상이다. 줄 저장·취소·이동·삭제 뒤 초점이 그 줄이나 이웃 줄에 남고, 지시 목록과 메뉴의 Esc는 대화 창을 닫지 않는다. 글과 줄을 오가도 내용이 같다. 120줄·8명에서 개발 서버 기준 줄 보기 93ms, 줄 열기 71ms, 입력 6ms, 강조 36ms, 이동 19ms였다. 바뀐 1줄 만들기는 4초, 순서만 바꿔 잇기는 3.6초 걸렸다. 한글 조합 중 Enter와 조합을 끝낸 뒤 코드 229로 오는 Enter(Safari)는 저장하지 않으며, 조합 중 Esc는 편집을 닫지 않는다. 접근성 트리에서 대화·줄 편집·지시 목록·목소리 설정·한 목소리 화면의 조작 요소 45~89개에 모두 이름이 있고, 줄에 초점이 가면 화자와 대사를 함께 읽는다. VoiceOver로 직접 듣지는 않았다.

## 위험

- 한글 조합 중 Enter로 줄이 나뉘지 않게 해야 한다.
- 120줄을 모두 편집기로 그리면 느려질 수 있어 고른 줄만 편집기로 바꾼다.
- 색을 저장하기 전 프로젝트는 등장 순서로 색을 정하므로 장면마다 색이 달라질 수 있다. 첫 저장 뒤에는 유지한다.
