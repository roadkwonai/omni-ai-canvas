| 범위 | 제작 흐름 | 인수 기준 |
| --- | --- | --- |

## 화면과 데이터 흐름

대본을 열면 해당 노드의 텍스트를 합성 입력으로 가져온다. 감독안의 VO 음향 큐는 발화 원문만 채운다. 제작자는 발화할 문구를 확인하고 한 번에 최대 2,000자를 보낼 수 있다. 기존 음향 큐에 적용하면 타임라인 연결이 이어지고, 대본·시나리오에서 적용하면 원본에 연결된 음향 큐를 추가한다.

등록 샘플 제작은 선택한 이미지에 종속되지 않는 도구다. 왼쪽 제작 키트의 **제작 도구**에 대표 진입점을 두고 보드 상단 제작 도구 목록과 캐릭터 노드에도 바로가기를 둔다. 전용 화면에는 추가 대상, 공급사별 목소리 선택, 대사와 결과를 배치한다. 넓은 화면에서는 목소리와 대사를 두 열로 배치하고 좁은 화면에서는 한 열로 읽는다.

전용 화면은 Fish Audio를 우선 선택한다. 목록에서 선택한 목소리의 샘플을 해당 행에서 재생한다. 여러 페이지를 탐색할 수 있으며, 제공 샘플이 없으면 짧은 합성으로 확인한다. 완성한 샘플은 로컬에서 재생·다운로드할 수 있다. **캐릭터에 샘플 추가**는 선택한 시트에 음성 파일을 보관한다. 캐릭터 설정에서는 보관한 샘플을 재생하고 Higgsfield 연결과 사용 권한을 확인한 뒤 등록한다.

Fish Audio 공개 목록은 기본 목록과 공식 API의 언어별 조회에서 100개씩 받아 Postgres에 저장한다. 같은 목소리 ID는 한 건으로 합친다. 목록에서 새 언어 코드가 발견되면 조회 계획 끝에 추가하고, 중단되면 저장한 언어 범위와 페이지부터 이어받는다. 계정 API가 반환하는 조회 범위별 상한이 있어, 저장 수량은 공식 API로 확인한 공개 목록 범위를 나타낸다. **목록 갱신**은 백그라운드에서 진행되고 기존 목록도 그동안 검색할 수 있다. 인기순은 공급사의 생성 사용 횟수, 최신순은 공급사의 생성일을 쓴다. 성별과 태그는 공급사 원본을 사용한다. 원문과 저장된 한국어 제목·설명을 DB에서 검색하고, 한국어 검색 결과가 비면 검색어를 영문으로 바꿔 다시 조회할 수 있다. [Fish Audio 목록 API](https://docs.fish.audio/api-reference/endpoint/model/list-models)

Fish Audio DB 목록은 100개씩 읽고, 스크롤이 끝에서 800px 안으로 들어오면 다음 페이지를 이어 읽는다. 이어 읽는 동안 선택과 입력은 계속 사용할 수 있다. 실패하면 목록 끝의 **다시 불러오기**로 재시도하고, 검색 조건을 바꾸면 처음 위치로 돌아간다. 화면 밖의 행은 `content-visibility`로 그리기를 미룬다. 넓고 높은 화면에서 목록의 스크롤 영역은 두 열 작업 화면의 남은 높이를 사용한다. 백그라운드 번역 작업이 아직 번역되지 않은 제목과 설명을 원본과 함께 DB에 보관한다. 목록은 저장된 한국어 값을 조회하며, 준비 중인 항목은 원문을 표시한다. 태그도 한국어 이름을 별도로 보관한다. 원본 이름과 설명은 선택한 행에서 열람할 수 있다.

Fish Audio 제목·설명·태그와 영문 검색어는 Claude 구독의 중첩 Claude Code 세션(`claude -p`)에서 `claude-haiku-5-5`로 번역한다. 음성 번역 전용 워커는 최대 세 묶음을 동시에 처리한다. 묶음은 최대 20건이며 원문 JSON 길이에 맞춰 줄인다. 끝난 묶음부터 DB에 저장하고 빈 자리에서 다음 묶음을 시작한다. 태그 번역을 같이 시작한 목록 갱신 워커는 음성 번역을 두 묶음으로 실행해 총 동시 요청 수를 유지한다.

성별은 **전체·남성·여성** 중 하나를 고른다. 연령대·언어·태그는 팝업에서 **전체** 또는 여러 값을 골라 적용한다. 같은 항목의 여러 값에는 OR, 서로 다른 항목에는 AND가 적용된다. 같은 한국어 이름의 태그를 선택하면 해당 원본 태그들을 함께 적용한다. 언어는 Fish Audio가 제공하는 목소리 언어 코드다.

대상 캐릭터를 고르고 **캐릭터에 맞는 목소리 추천**을 누르면 현재 필터에 맞는 DB 목록 전체를 살핀다. 캐릭터 시트에 명시된 성별·연령대·발화 언어와 후보의 메타데이터를 대조해 어긋나는 후보를 제외한다. 말투 단서에 가까운 후보와 다양하게 구성한 후보를 작업실 텍스트 에이전트에게 보내 연기 상황과 공급사 설명을 비교한다. 결과는 확인한 조건과 후보 적합도 순으로 최대 다섯 명의 한국어 이유를 표시한다. 추천 목록에서 미리듣기를 재생하거나 전체 목록으로 돌아갈 수 있다.

서버의 프로젝트 TTS API에서 공급사 설정 상태, 음성 목록, 합성을 제공한다. 공급사 키는 서버의 기존 비밀 저장소에서 읽는다. 합성 결과는 기존 프로젝트 미디어 형식으로 저장한다. 공급사 카탈로그와 미리듣기는 합성 요청을 제출하지 않는다. 합성은 공급사 API 요금제를 따르며, Higgsfield에 개인 목소리를 등록할 때 해당 계정의 조건이 적용된다.

## 로컬 무료 생성

| 범위 | 제작 흐름 | 인수 기준 |
| --- | --- | --- |
| C3·C8 로컬 합성 | Fish Audio 목소리를 고르고 **생성 모델**에서 S2 Pro나 Drama 3를 선택한다. **내 음성 · 로컬 무료**에서는 기본 목소리, 캐릭터 샘플, 프로젝트 음향을 고른다. | 설치하지 않은 모델은 선택할 수 없다. 참조 음성은 권한 확인 뒤에만 쓴다. 진행 상태를 표시하고 취소할 수 있다. 결과는 기존 적용 흐름을 따른다. |

로컬 모델에는 Fish Audio의 목소리 ID가 없다. 선택한 목소리의 공개 샘플과 원문을 참조로 보내 같은 음색으로 생성한다. 공개 중단되거나 라이선스가 제한된 목소리는 참조하지 않는다. 참조 음성은 60초까지 쓴다. 모델 라이선스는 선택한 모델 아래에 표시한다.

2026-11-24 M1 Ultra 64GB에서 문장 6개를 모델별로 30회씩 번갈아 만들었다(참조 24회, 참조 없음 6회). 두 모델 모두 30회 중 30회 성공했고 클리핑은 없었다. 음성 1초당 생성 시간의 중앙값은 S2 Pro 8bit 참조 1.05초·참조 없음 0.94초, Drama 3 4bit 0.65초였다. 모델 올리기는 두 번째부터 S2 1.7초, Drama 3 약 7초였다. 로컬 Whisper 전사 오류의 중앙값은 S2 1.5%, Drama 3 3.3%, Fish 공개 샘플 18개 3.6%로 전사기의 오차 안에 있다. 숫자를 아라비아 숫자로 받아 적는 문장이 오류의 대부분이다. 음색 유사도와 청취 품질은 재지 않았다. 번역 작업이 함께 도는 상태에서 쟀다.

공식 제어 문법은 [Drama 3 기술 보고서 부록 C](https://arxiv.org/html/2610.18010), [S2 Pro 모델 카드](https://huggingface.co/fishaudio/s2-pro), [mlx-audio 문서](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/fish-drama3.md)를 2026-11-24에 대조했다. 화면에 넣지 않은 것과 이유는 다음과 같다.

| 제외한 항목 | 이유 |
| --- | --- |
| 한 대사 안의 여러 화자(Drama 3 최대 16명) | 캐릭터 한 명의 샘플에는 쓰지 않는다. 대본에서는 아래의 여러 화자 대화로 만든다. |
| 화자당 참조 음성 여러 개 | 참조 선택 화면이 한 개를 고르는 구조다. 효과를 재지 않았다. |
| 음성 일부만 다시 채우기(infill) | mlx-audio 0.6.7이 제공하지 않는다. |
| 언어 힌트 | 한국어와 섞어 쓴 문장에서 차이가 없었다(3회). 공식 문서도 각 줄은 대사의 언어로 읽는다고 적는다. |
| 앞 음성과 비교하는 지시(`versus previous`) | 앞 연기를 거의 그대로 복사해 지시가 듣지 않았다. 목소리만 참조하고 지시를 붙이는 방식으로 바꿨다. |
| 최대 토큰, 스트리밍 간격, 반복 방지 값 | 결과를 고르는 옵션이 아니라 실행 설정이다. |

2026-11-24 추가 실측. 목표 길이는 여자아이·중년 여성·노년 남성 설계에서 8·9·10·14초 지정이 대부분 0.1초 안으로 맞았다(조합별 2회, 최대 오차 0.9초). 자연스러운 길이(7.2초)보다 짧은 3·5초를 지정하면 뒤쪽 말이 빠져, 글자당 0.2초보다 짧은 값은 받지 않는다. 길이를 줄일 때는 말하는 속도를 쓴다. 대사 지시는 뜻 없는 태그와 길이·음량·음높이를 비교해 골랐다(2회씩). Drama 3의 `soft`, `low-pitched`, `breathy` 감싸기와 `gulps`, `screams`, `clicks tongue`는 차이가 없어 넣지 않았다. S2 Pro의 공식 지시는 다른 문장의 참조로 두 자리에서 쟀고 웃음·기침·헛기침 등 6종만 길이가 늘었다. 다시 연기는 대사만 고치면 앞 음성을 먼저 한 연기로 들려주고(길이와 음높이가 앞 음성과 같은 수준), 지시가 있으면 목소리만 참조한다. 같은 대사를 다시 읽을 때 속삭임은 6회 중 5회 들었고 빠르게·슬프게·크게는 약했다. 대사 앞 지시, Direction/Line, 문장별 반복을 비교해 대사 앞 지시를 골랐다. 청취 평가는 하지 않았다. 측정 프로세스가 같은 GPU를 함께 쓰는 동안 앱의 생성이 2분 넘게 멈춘 적이 있으며 단독 실행에서는 재현되지 않았다.

목소리 설계는 왼쪽 열, 대사와 연기는 오른쪽 열에 둔다. 생성 버튼과 진행 상태는 아래에 고정해 긴 옵션 목록에서도 보인다. 캐릭터 시트에 적힌 성별과 나이를 한 번에 가져온다. 만든 음성은 최근 다섯 개를 설정·시드와 함께 남기고, 같은 설정과 시드를 다시 쓸 수 있다. 캐릭터에 저장한 음성은 다음 생성의 참조가 되며 실제로 읽은 말을 함께 보관해 다시 받아쓰지 않는다.

2026-11-24 실측. 같은 문장의 음높이 중앙값은 Drama 3에서 여자아이 313~377Hz, 20대 여성 244~298Hz, 중년 여성 186~216Hz, 중년 남성 114~125Hz, 노년 남성 92~141Hz로 갈렸다(조합별 3회). S2 Pro는 시스템 지시와 대사 앞 지시 모두 성별·나이를 바꾸지 못해 설계를 막았다(조합별 2회). 음높이 지시는 남성 목소리에서 듣고 여성 목소리에서는 차이가 없었다(4회씩). 같은 시드는 같은 파일을 만들었다. 지시문을 소리 내어 읽지 않았으며 전사 오류 중앙값은 0이었다.

### 여러 화자 대화

| 범위 | 제작 흐름 | 인수 기준 |
| --- | --- | --- |
| C3·C8 대화 합성 | 대본·시나리오의 **대사 음성 만들기**에서 **여러 화자 대화**를 고른다. 대본에서 읽은 대화를 고치고 화자마다 목소리를 정해 Drama 3로 합성한다. | 화자가 적힌 줄만 읽고 뺀 지문 수를 보여준다. 줄별로 듣고 한 줄만 다시 만들 수 있으며 다른 줄은 바뀌지 않는다. 결과는 원본 대본에 연결된 음향 큐가 된다. |

화자는 `화자: 대사`, `**화자** 대사`, `**화자:** 대사`, `[화자] 대사`, `[VO]·[OS] 화자: 대사`로 읽는다. 화자 뒤나 대사 앞의 괄호는 `[지시]`로 바꾸고, 화자 앞에 적은 `[한숨]`·`[속삭임]` 같은 지시도 그 줄의 지시로 읽는다. 지문, SFX, 화면문자, 제목, 표, 장소·시간, 번호 붙은 장면, 시각(밤 11:40), 주소는 읽지 않는다. 화자 이름은 세 낱말·20자 안의 글자와 숫자이며, 다른 부호는 띄어쓰기로 바꿔 글과 줄을 오가도 같은 이름이 되게 한다. 줄에서 정하는 이름도 같은 규칙으로 확인한다. 읽은 결과는 `화자: 대사` 글로 보여주며 고칠 수 있다. 화자가 둘 이상인 대본은 이 화면을 먼저 연다.

목소리는 프로젝트의 음성 샘플이나 새로 설계한 목소리에서 고른다. 화자 이름과 맞는 캐릭터의 샘플을 먼저 쓰고, 없으면 시트의 성별·나이로 설계한다. 설계한 목소리는 이름과 설계에서 정한 시드로 표본 문장을 한 번 읽히고 그 소리를 모든 줄이 참조하므로 다른 장면에서도 같은 목소리가 난다. **다른 목소리**를 누르면 시드가 바뀐다. 화자별 선택은 이 브라우저에 프로젝트별로 남는다. Fish Audio 목록의 목소리는 캐릭터 샘플로 저장한 뒤 고른다. 한 번에 대사 2,000자, 120줄, 8명까지 만든다.

한 번에 여러 화자를 합성하는 Drama 3의 화자 태그는 쓰지 않는다. 2026-11-24에 화자 3명 8줄과 4명 10줄을 세 번씩 만들어 비교했을 때, 네 번째 화자(남성)의 첫 줄이 세 번 모두 여성 음높이(292~308Hz)로 나왔다. 줄마다 만들면 세 번 모두 135~144Hz로 맞았고 걸린 시간도 비슷했다(37초 분량에 25~32초). 줄마다 참조 음성의 크기를 맞추고 앞뒤 무음을 0.05초로 다듬어 정한 쉼만큼 띄워 잇는다(대사에 적은 쉼은 남긴다). 다듬기 전에는 0.4초로 정해도 0.66~1.21초 쉬었고 지금은 0.46~0.59초다. 줄의 시드를 순서가 아니라 화자와 대사로 정해 줄을 끼워 넣거나 고쳐도 다른 줄이 같은 소리를 낸다. 만든 줄은 워커가 최대 200줄까지 보관하고 오래 쓰지 않은 줄부터 버리며, 진행률은 새로 만드는 줄로만 계산한다. 다시 만들 때 보관한 줄을 재사용한다(한 줄 교체 7초, 처음 6줄 76초).

실제 대본 세 편의 58줄을 만들어 실패와 비정상 길이가 0줄이었다. 줄별 로컬 Whisper 전사에서 53줄이 오류율 0.3 이하였고, 나머지 5줄은 숫자를 아라비아 숫자로 받아 적거나 이름·짧은 말을 다르게 들은 경우다. 4명 12줄을 세 번씩 만들어 잰 값은 클리핑 0, 이음매 최대 진폭 0.006, 통합 음량 -20.6~-21.1 LUFS, 화자별 크기 차이 3.1dB 이내다. 같은 화자의 줄은 다른 화자보다 스펙트럼이 가깝다(1.10과 1.87, 지시가 없을 때). 연기의 자연스러움은 사람이 듣고 평가하지 않았다.

대화는 화자 색 태그, 한국어 지시 태그, 대사, 상태, 줄별 작업을 한 줄에 둔 대본형 줄로 보여준다. 지시는 화면에서 한국어, 저장과 합성에서 모델의 지시를 쓰며 글로 편집할 때 한국어로 적어도 같은 지시로 읽는다. 줄 상태는 만든 소리의 화자·대사·목소리·다시 만든 횟수와 비교한다. 설계와 검증은 [가독성 개선](dialogue-readability-plan.md)에 있다.

### AI 연기 지시

한 목소리와 여러 화자 대화에서 **AI로 연기 지시 넣기**를 누르면 작업실 텍스트 에이전트가 대본·등장인물과 대사를 읽고 소리·쉼, 감싸는 지시, 말투를 고른다. 선택한 모델이 쓰는 지시 중 효과를 확인한 것만 쓴다. 서버는 줄마다 소리 낼 말의 글자·문장부호·띄어쓰기가 같은지, 사용자가 넣은 지시가 같은 자리에 남았는지, 새 지시가 목록에 있고 짝이 맞으며 네 개 이하인지 확인하고, 하나라도 어긋나면 그 줄은 원문을 쓴다. 한 목소리는 넣은 줄과 이유를 목록으로, 여러 화자 대화는 줄의 AI 버튼으로 보여주고 줄별·전체로 되돌린다. 손으로 고친 줄은 되돌리기 대상에서 뺀다. 다시 고를 때는 AI가 넣기 전의 글에서 시작한다. 한 목소리는 문장으로 나눠 보내고, 말투는 모든 문장이 같을 때만 전체에 적용한다.

2026-11-24 작업실 기본 에이전트(Codex, 구독)로 실제 대본 두 편을 확인했다. 12줄 중 8줄, 23줄 중 7줄에 지시를 넣었고 대사가 바뀐 줄은 없었다. 응답은 12~21초였다. 지시를 넣은 12줄을 합성해 줄별로 전사했을 때 지시를 읽은 줄은 없었다. 같은 시드로 지시 유무를 비교하면(3회 평균) 외침은 259→405Hz·+2.9dB, 크게는 186→272Hz, 천천히는 길이 1.27배, 낮은 음은 195→164Hz였고 쉼은 0.2~0.3초, 강조는 차이가 작았다. 지시가 없는 네 줄은 길이·크기·음높이가 같았다. 지시가 연기를 더 낫게 하는지는 사람이 듣고 평가하지 않았다.

### 진행 상태

단계는 대기, 준비, 모델 올리기, 음성 생성, 마무리다. 앞선 작업 수, 문장 묶음, 만든 길이, 경과 시간, 남은 시간을 1초마다 갱신한다. 모델 올리기는 이전에 걸린 시간으로, 생성은 실제로 만든 양과 속도로 계산한다. 진행률은 줄어들지 않고 완성 전에는 100%가 되지 않는다.
