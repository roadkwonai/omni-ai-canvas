# Blender 3D 장면 실증

검증일 2026-11-22. Omni AI Canvas의 로컬 개발 서버와 Neon 프로젝트에서 기존 GLB 파일 업로드부터 실제 Blender 렌더와 타임라인 출력까지 한 장면을 확인했다. Tripo3D와 이미지·영상 생성 서비스는 호출하지 않았다.

## 장면과 자산

장면 **숲길에서 만난 여우**는 여우가 돌이 놓인 숲길에서 제자리 걸음 동작을 반복하고 카메라가 천천히 가까워지는 2초 샷이다. Blender는 로컬 설치된 5.3.0을 사용했다.

## 실행과 확인

1. 프로젝트 API로 새 프로젝트를 만든 뒤 GLB 자산 두 개를 업로드했다. Omni AI Canvas는 Fox의 스킨 뼈와 세 액션, Kenney 배경 메시를 목록에서 식별했다.
2. 같은 장면 설정으로 프리비즈를 실행했다. 결과는 H.264, 640×360, 24fps, 2초다. 0.1초와 1.8초 프레임에서 여우의 다리 위치와 카메라 구도가 달라지는 것을 확인했다.
3. 같은 설정으로 최종 렌더를 실행했다. H.264, 1280×720, 24fps, 2초다. 가운데 화면에서 나무·돌·잔디 배경과 여우의 질감·조명을 확인했다.
4. 최종 테이크를 기존 Omni AI Canvas 타임라인에 연결하고 최종 MP4를 만들었다. 결과는 H.264, 1280×720, 30fps, 2초이며 무음 AAC 트랙을 포함한다. 타임라인은 24fps 소스를 30fps로 정규화한다. 출력 프레임과 최종 렌더 화면이 이어지는 것을 육안으로 확인했다.
5. Neon에서 샷 설정, 프리비즈·최종 테이크, 타임라인 클립과 타임라인 결과 자산을 다시 읽었다. 브라우저에서 샷의 **Blender 장면 다시 편집**을 열고 Fox, Kenney 배경과 Walk가 복원되는 것을 확인했다.

이 장면은 단일 GLB 캐릭터와 하나로 합친 배경을 사용하는 로컬 검증이다. 포즈의 시각적 의도나 임의의 외부 리그 호환성은 캐릭터마다 별도 확인이 필요하다. 배경의 검은 하늘은 Blender 기본 월드 색이다.

## 탑뷰 블로킹과 대안 앵글

같은 프로젝트에 기존 캐릭터, Kenney 배경과 Walk 동작을 유지한 **숲길 공간 확인 · 탑뷰** 샷을 추가했다. 위에서 내려다보는 1초 프리비즈를 만든 뒤 0.5초 프레임을 기존 클립 도구로 추출했다. 화면에서 여우, 바닥의 돌, 양옆의 나무 위치를 확인할 수 있다.

추출 프레임은 **블로킹 참조** 이미지 노드로 저장하고 대안 앵글 샷에 연출 확인용으로 연결했다. 대안 샷은 기존 캐릭터·배경·동작을 유지하며 카메라를 반대쪽 시작 위치 [-4,5,2.4]와 끝 위치 [-3.5,5.3,2.2]로 바꾸었다. 반대편 화면에 맞춰 조명 위치는 [-3,4,6], 에너지는 800으로 조정했다. 대안 샷에는 blocking과 shot-plan 지침 선택이 보존된다. 동일 설정의 로컬 프리비즈에서 여우의 뒷모습과 주변 나무·돌을 확인했다.

- [반대 앵글 프리비즈](http://127.0.0.1:5050/api/assets/4626bcd8-4068-4d34-b513-4321fac1803e.mp4)

Neon 재조회에서 탑뷰 테이크 → 블로킹 참조 → 대안 샷의 두 연결이 모두 연출 확인용임을 확인했다. 기존 제공자 입력 수집 함수에 대안 샷을 넣어 블로킹 이미지가 자동 첨부되지 않는 것도 확인했다. 처음의 4개 노드와 최종 테이크·타임라인 결과를 보존한 상태로 전체 9개 노드와 7개 연결이 있다. 이 검증에서는 외부 AI를 호출하지 않았다.
