## 1. 제작자가 할 수 있어야 하는 일

숏드라마 제작자는 프로젝트를 만들 때 형식을 고르고, 첫 장면에 필요한 대본·배역·샷·키프레임이 연결된 보드에서 시작한다. 이미 만든 캐릭터 시트의 사진을 선택해 **질감 보정**을 누르면 그 사진이 입력으로 연결된 편집 노드가 생긴다. 제작자는 사용할 이미지 모델과 변경할 부분을 보고 실행한 뒤, 원본과 결과를 비교해 다음 샷의 기준을 고른다.

새 프로젝트에서 **형식 지정으로 시작**과 **무형식으로 시작**을 나란히 제공한다. 개인 보관함의 **내 프리셋으로 시작**도 선택할 수 있다. 두 제작 방식 모두 완성된 작업에서 프리셋을 저장할 수 있다.

## 3. 새 프로젝트와 작업 후 프리셋

**형식 지정으로 시작**을 누르면 숏드라마·드라마·영화·광고·모션그래픽·뮤직비디오 등에서 선택한다. 형식을 누르면 시작 보드의 축소 미리보기, 화면비·예상 길이·씬 수, 추천 지침과 도구를 보여준다. 값을 수정한 뒤 **이 구성으로 시작**하면 프로젝트와 초기 그래프를 함께 저장한다. 이 시점의 산출물은 편집 가능한 보드다. 에이전트 기획과 이미지 생성은 캔버스에서 별도로 실행한다.

지침과 스킬은 **어느 노드에서 쓰는지**까지 미리보기로 제시한다. 예를 들어 숏드라마의 기획 노드에는 `story-hook`, 배역에는 `casting-continuity`, 샷에는 `acting`과 `blocking`을 추천한다. 광고의 제품 컷은 `product-photo`, 검수는 `commercial-check`를 추천한다. 모션과 음향은 설치된 로컬 레시피·Road Music 경로를 제안한다. 각 항목의 출처·적용 단계·중복 추천을 펼쳐 보고 교체하거나 끌 수 있다. 형식 기본값을 적용한 뒤 사용자가 수정한 노드 지시가 우선한다. [제작 지침 카탈로그](../lib/higgsfield-guidance-kit.ts) · [스킬·제작 자료 대응표](production-reference-map.md)

**무형식으로 시작**을 누르면 제목만으로 노드 0개·연결 0개의 보드를 연다. 첫 ＋에서 대본을 써도 되고, 기존 캐릭터 시트·음원·레퍼런스 영상을 먼저 올려도 된다. 다음 ＋에서 후속 노드와 연결을 하나씩 정한다. 형식 프로필, 기본 스킬 묶음, 씬 수, 화면비는 자동 배정하지 않는다. 각 노드에 필요한 지침을 선택하며, 출력 규격은 해당 이미지·영상 작업 또는 내보내기에서 지정한다. 에이전트 추천을 요청해도 적용할 노드는 제작자가 고른다.

예를 들어 **무형식 → 캐릭터 시트 첨부 → 질감 보정 → 감정 후보 2개 → 한 테이크 채택 → 9앵글 → 선택한 컷으로 영상 → 내보내기**까지 프로젝트 형식을 비워 둔다. 도중에 광고로 방향을 정하면 그때 형식 권장값과 보드 변경 미리보기를 열 수 있다. 반대로 형식 지정 프로젝트에서도 **무형식으로 전환**을 선택할 수 있다. 이후 새 노드의 형식 추천을 해제하고 기존 노드·연결·채택본·노드별 지침은 유지한다. 두 전환 모두 예상 변경을 확인한 뒤 적용한다.

**현재 보드 → 프리셋으로 저장**에서는 현재 그래프 전체 또는 선택한 묶음을 미리 보여준다. 제작자는 유지할 역할·연결·노드별 지침·연출 기본값을 선택하고, 교체할 항목을 ‘주연 이미지’, ‘제품 사진’, ‘음원’ 같은 입력 자리로 지정한다. 경계를 넘어오는 연결은 새 입력 자리로 표시한다. 프리셋은 이름을 붙여 형식 미지정으로도 저장할 수 있다. 새 프로젝트에서 열면 새 노드 ID를 발급하고 내부 연결을 다시 매핑한다. 개별 작품 대사, 원본 자산 경로, 실행 이력과 계정 정보는 재사용 대상에서 기본 제외한다.

기존 프로젝트는 처음에 ‘무형식’으로 해석한다. 작업 중 형식을 지정하거나 변경할 때 **추천 도구·지침만 적용**과 **빠진 기본 노드도 추가**를 선택한다. 추가될 노드·연결·설정 차이를 먼저 보여주고, 사용자가 채택한 샷이나 직접 편집한 노드를 보존한다. 같은 구성을 재적용해도 기본 노드가 중복되지 않게 템플릿 역할을 기록한다. 프로젝트 카테고리·태그는 검색용으로 유지한다.

## 4. 캐릭터 시트에서 이미지 편집 시작

기능을 고르는 즉시 원본에 파생 노드를 붙이고 감정·카메라·조명 상태를 시각적으로 조절·저장하는 동작은 [기능 노드 재설계](character-direction-node-design.md)에서 구체화했다.

1. 이미지가 있는 캐릭터 시트·레퍼런스·키프레임에서 **이미지 편집** 또는 출력 포트의 **＋**를 누른다. 다면 시트라면 원본 전체와 특정 셀·인물 중 대상을 고른다. 입력 썸네일에는 실제로 보낼 원본이나 선택 영역을 표시한다.
2. 편집 종류를 고르면 연결된 파생 노드가 생긴다. 원본, 변경할 항목, 유지할 얼굴·헤어·의상·소품·구도를 보여준다. 생성 전에 프롬프트와 실제 전송할 이미지를 열어볼 수 있다.
3. 참조 이미지 편집을 지원하는 **계정 → 모델 → 작업 모드**를 고른다. 모델이 지원하는 화면비·품질·출력 해상도·수량과 참조 슬롯을 표시한다. 견적과 실행 방식을 확인한 뒤 제출한다.
4. 결과에서 원본/후보의 동일 위치를 확대해 얼굴, 피부결, 의상, 손·소품, 배경 변화를 비교한다. **이 테이크 채택**으로 후속 노드의 입력을 정하거나 같은 원본에서 다른 테이크로 분기한다. 재편집의 기준이 원본인지 직전 테이크인지 표시한다.

| 편집 작업 | 편집자가 지정하는 값 | 결과와 검수 |
| --- | --- | --- |
| 인물 질감 보정 | 인물과 배경 경계의 융합, 인물과 주변광의 일치, 피부결, 입자감, 디테일 선명도. 각 축은 3단계부터 제공한다. 출력 픽셀 수와 선명도 지시는 별개로 노출한다. | 같은 얼굴·의상·포즈를 유지한 보정 테이크. 얼굴 확대에서 모공, 과도한 샤프닝, 경계 번짐을 비교한다. 여러 번 강하게 적용한 결과도 최초 원본과 비교할 수 있다. |
| 감정 조정 | 대상 얼굴을 직접 선택하고 친밀함↔거리감, 평온↔흥분을 고른다. 이름이 있는 표정 프리셋, 강도, 시선·눈썹·입가에 대한 행동 지시로 세분화한다. 한 번에 한 인물을 기본으로 한다. | 제어판에는 ‘긴장 2단계 · 시선을 피하고 입술을 다문다’처럼 보이는 변화를 적는다. 다인 이미지에서는 다른 인물과 배경도 함께 검수한다. 자동 얼굴 후보는 후속 옵션이며 수동 상자를 먼저 지원한다. |
| 다각도 편집기 | 기준 방향을 정하고 수평 회전, 수직 피치, 샷 크기를 조절한다. 정면·사선·측면·후면·부감·앙각 프리셋과 숫자 입력을 제공한다. | 작은 도식은 카메라 의도를 미리 보여준다. 한 장에서 보이지 않던 뒷면은 모델이 추정하므로 의상·소품 연속성을 확인한다. 실제 3D 카메라가 필요한 샷은 기존 Blender 장면으로 연결한다. |
| 조명 효과 | 주광 방향, 밝기, 색·색온도, 그림자 부드러움, 림라이트를 조절한다. 미리보기의 광원 위치를 키보드와 터치로도 바꿀 수 있다. | 얼굴과 배경에 떨어지는 빛이 일치하는지 본다. 화면에서 가능한 노출·색 미리보기와 모델이 새로 계산한 그림자 결과를 구분한다. |
| 시네마틱 조명 보정 | 씬 의도와 기준 룩 이미지, 키·필 대비, 피부 톤, 하이라이트, 그레인을 선택한다. 기본 설정에서는 인물 위치와 샷 크기를 고정하고, 재구도는 별도 선택으로 둔다. | 예시로 ‘늦은 오후 창가의 역광’ 테이크를 만들고 앞뒤 승인 컷과 비교한다. 조명 효과와 동일한 편집 경로에 룩과 연속성 검토를 더한다. |

**모델 호환성**은 ‘원본 이미지 편집’, ‘대상 영역 지정’, ‘여러 결과’, ‘실제 출력 규격’별로 확인한다. 공급사의 명시적인 옵션은 실제 파라미터로, 질감이나 연기처럼 언어로 전달하는 값은 **프롬프트 지시**로 표시한다. 엄밀한 영역 보존이 필요한 요청에서 마스크·영역 지정 지원을 확인할 수 없으면 전체 이미지 변형의 영향을 설명하고 다른 모드를 고르게 한다. 출력은 픽셀 크기를 읽어 표시한다. 시트 화면비나 그림 속 4K 표기가 개별 컷 해상도를 보장하지 않는다. [OpenAI 이미지 편집](https://developers.openai.com/api/docs/guides/image-generation) · [Gemini 이미지 편집](https://ai.google.dev/gemini-api/docs/image-generation) · [Seedream 편집 가이드](https://docs.byteplus.com/en/docs/modelark/seedream-5-0-pro-editing-guide)

**계정과 비용**은 기존 구독 CLI·공식 MCP·이미지 API·외부 앱 인계 경로를 재사용한다. Codex는 설치 환경의 이미지 도구와 원본 전달 가능 여부, Antigravity는 앱 인계 후 결과 가져오기, API는 현재 어댑터와 계정 권한을 각각 표시한다. Higgsfield·Kling·Topview는 계정별 모드와 입력 슬롯을 확인한다. 참고 영상에 등장한 모델명·할인·응답시간은 기본값에 넣지 않는다. 다중 출력 지원이 없을 때는 한 장으로 시작한다. 여러 호출을 선택하면 **호출 수와 예상 비용 또는 견적 미확인**을 먼저 표시한다. [프로젝트의 계정·모델 경로](providers.md) · [현재 모델 입력 해석](../lib/media-request.ts)

## 5. 9앵글과 25컷의 제작 방식

| | 멀티카메라 9그리드 | 연속 스토리보드 25그리드 |
| --- | --- | --- |
| 공통 입력 | 기준 이미지·고정 배역·공간·같은 순간의 행동 | 기준 이미지·씬의 시작과 끝·대본 또는 편집 가능한 전개 초안 |
| 칸마다 달라지는 것 | 카메라 위치와 샷 크기. 예를 들면 같은 컵을 드는 순간의 정면·오버숄더·손 인서트 | 시간에 따른 사건·행동·반응. 예를 들면 컵을 발견 → 다가감 → 집음 → 표정 전환 → 자리를 떠남 |
| 기본 흐름 | 앵글 목록 검토 → 3×3 시트 후보 → 칸 선택 → 선택한 앵글을 키프레임으로 채택 | 25개 비트 순서 검토 → 5×5 시트 후보 → 인물·동선·소품 연속성 확인 → 컷 선택 → 키프레임·영상·타임라인 연결 |
| 수정 단위 | 원하는 칸의 각도만 변경해 재요청 | 특정 컷의 행동·시점을 고치고 인접 컷을 참조해 그 칸만 재요청 |

시트 한 장을 생성한 뒤 기존 로컬 분할기를 확장하는 방식을 우선한다. 자동 분할 전 행·열, 여백, 간격과 경계를 겹쳐 보여준다. 모델이 틀린 수의 칸을 그리면 다시 맞추거나 검수에서 제외한다. 셀별 생성·고해상도 재생성은 선택한 컷에만 요청한다. 예를 들어 3840×2160의 5×5 시트는 여백이 없어도 한 칸이 약 768×432다. 보드 검토에는 충분해도 클로즈업 영상의 첫 프레임으로 채택할 때는 원본과 함께 개별 재생성을 선택할 이유가 있다.

샷 ID·셀 번호·원본 시트·채택 이미지의 관계를 보관한다. 한 칸을 다시 만들어도 다른 24칸의 채택 상태와 타임라인 순서가 유지되어야 한다. 25컷 보드에 이미 샷·키프레임이 있으면 대응 슬롯에 연결한다. 전체 확장 전 현재 그래프의 120노드·500연결 한도와 추가 수를 보여주고 선택한 컷만 펼칠 수 있게 한다. [기존 분할기](../components/PortraitGridStudio.tsx) · [그래프 제약](../lib/graph.ts)

참고 화면에서 추가로 보이는 **4컷 전개, 얼굴 3면도·전신 3면도, 캐릭터·장면·제품 설정도**는 같은 시트 틀에 ‘칸의 목적’을 바꿔 확장할 수 있다. **파노라마, 레이어 분리·요소 편집, 전후 시점의 화면 추론**은 별도 검증 대상으로 둔다. 특히 정지 이미지에서 ‘3초 후’를 만드는 기능은 추정한 장면을 생성하는 작업이다. 실제 영상의 해당 시각에서 프레임을 추출하는 기존 작업과 진입점과 결과 표시를 달리한다. 메뉴에 보인 기능의 내부 처리 방식은 확인되지 않았다.

툴바의 **고화질**도 별도 동작으로 취급한다. ‘더 큰 원본 생성’, ‘기존 이미지 업스케일’, ‘디테일을 다시 그리는 생성 편집’ 중 현재 계정과 모델이 수행할 수 있는 작업을 보여준다. 원본 크기와 실제 결과 크기를 표시한다. 스테이징 스토리보드는 기존 샷 배치·프리비즈와 연결해 대상 인물, 카메라, 장면 순서를 수정하는 경로로 검토한다.

## 6. ＋ 버튼과 연결선

- 이미지가 있는 카드의 **출력 포트 옆 ＋**를 누르면 ‘이 이미지로’ 가능한 작업이 열린다. 질감, 감정, 시점, 조명, 시트, 영상으로 이어진다. 입력 쪽 ＋는 연결할 기존 원본을 고르거나 새 참조 노드를 앞에 만든다. 원본 자산이 없으면 이미지 첨부·생성부터 제안한다.
- 포트 드래그 영역과 ＋ 클릭 영역을 분리한다. 새 노드의 배치와 연결은 한 번의 편집으로 저장하고 실행 취소 한 번으로 되돌린다. 이미 연결된 노드와 순환 연결은 기존 그래프 검사를 따른다. 메뉴는 터치에서 항상 찾을 수 있고 키보드로 열고 닫을 수 있어야 한다.
- **대기**는 정적 대기 표시, **실행 중**은 실제 입력 연결의 소스→대상 방향으로 흐르는 선, **검토 대기**는 결과 노드의 선택 가능한 표시, **실패**는 해당 노드의 원인·재시도로 표현한다. 연출 확인용 연결은 점선으로 둔다. 진행률은 공급사가 반환한 경우에 표시한다.
- 실행 연결은 현재 노드 실행의 입력 스냅샷과 작업 상태에서 파생한다. 선택한 노드의 직접 연결을 잠시 흐르게 하는 효과와 두 효과에 공통으로 적용하는 재생 상한·성능 기준은 [선택한 노드의 연결선 효과](character-direction-node-design.md#선택한-노드의-연결선-효과)에 정의한다.

## 7. 저장과 실행 경계 제안

| 대상 | 설계안과 실패 처리 |
| --- | --- |
| 프로젝트 제작 설정 | Neon 프로젝트에 선택적 제작 설정을 둔다. 상세 프로필 ID, 프로필 버전, 화면비·씬 수, 선택한 지침·도구를 저장한다. 감독용 형식은 상세 프로필에서 매핑한다. 무형식과 기존 프로젝트는 값이 비어 있어도 열린다. 새 프로젝트 생성과 초기 그래프 저장은 한 트랜잭션에서 처리한다. |
| 이미지 편집 노드 | 우선 기존 이미지 출력 노드에 선택적 편집 명세를 둔다. 작업 종류, 원본 노드와 **해당 자산 버전**, 대상 영역, 변경값·보존값, 출력 요청을 기록한다. 실행 시 원본의 실제 자산 참조, 모델·모드·적용된 파라미터·최종 프롬프트를 고정한다. 영역 좌표는 이미지 방향과 크기를 정규화한 뒤 공급사 규격으로 변환한다. |
| 결과·재시도 | 사용자에게는 원본 → 편집 노드 → 후보 테이크 → 채택본의 관계를 보여준다. 실행 중 소스가 교체되면 결과에는 당시 원본을 표시하고 재적용 시 충돌 여부를 검사한다. 같은 요청 ID를 중복 제출하지 않고, 여러 장 중 일부 실패는 실패한 항목만 사용자가 재요청한다. 공급사 취소 지원 여부도 상태로 표시한다. |
| 개인 프리셋 | 기존 스타일·비트 프리셋은 계속 읽는다. 후속 버전은 선택적 ‘보드 템플릿’을 포함한다. 노드 역할, 상대 위치, 입력 자리, 연결·지침·도구 설정을 저장한다. 형식 미지정 프리셋은 기존 필수 `profileId` 검증과 구분할 수 있게 스키마 버전을 둔다. 저장된 프리셋을 적용할 때 버전 사본을 프로젝트에 고정한다. |
| 권한·호환성 | 브라우저에는 모델의 표시용 기능표를 제공한다. 서버는 실행 직전에 프로젝트 소속·자산·모델·슬롯·출력 수량을 확인한다. 계정 토큰·다른 작품의 자산은 프리셋이나 프롬프트에 포함하지 않는다. |

현재 자산 값은 URL·종류·이름으로 구성된다. 편집용 원본 버전은 실행 입력에 프로젝트 ID, 원본 노드 ID, 자산 URL과 바이트 내용 해시를 함께 기록하는 안을 제안한다. 제출·재시도 때 같은 프로젝트의 파일을 대조하고, 사라지거나 바뀌었으면 원본을 다시 선택하도록 한다. 이렇게 하면 노드 제목이 같거나 시트가 교체돼도 예전 테이크가 어느 원본에서 나왔는지 알 수 있다. [현재 자산 자료형](../lib/types.ts)

## 8. 개발 순서와 인수 기준

| 순서 | 범위 | 완료 판정 예시 |
| --- | --- | --- |
| 1. 제작 진입 | 형식 지정, 무형식, 내 프리셋, 기존 보드에 나중 적용 | 숏드라마와 모션그래픽을 각각 만들면 첫 노드·지침·도구가 다르고 새로 열어도 보존된다. 무형식에서 노드를 하나씩 구성해 저장·재열기·내보내기·형식 미지정 프리셋 저장을 완료한다. 양방향 형식 전환 후에도 수동 노드와 채택 자산이 유지된다. 보드 준비 단계의 생성 호출은 0건이다. |
| 2. 인물 편집 한 경로 | 이미지 노드의 ＋, 편집 원본 고정, 모델 선택, 질감·감정, 원본/테이크 비교 | 이미 이미지가 붙은 **캐릭터 시트**에서 재업로드 없이 시작한다. 다인 이미지의 대상 선택과 비대상 검수가 가능하다. 동일 원본으로 만든 후보 2개의 입력·모델과 채택 여부를 추적한다. |
| 3. 카메라·조명 | 다각도, 수동 조명과 시네마틱 룩, 3×3 시트, 5×5 생성·분할·셀 재작업 | 같은 행동 9앵글과 순차 행동 25컷의 지시가 구분된다. 25컷 중 2·7·18번만 채택해 영상 노드에 연결할 수 있고 7번만 다시 만들어도 나머지 채택본이 보존된다. |
| 4. 작업 재사용과 상태 표시 | 완성 보드에서 프리셋 추출, 재적용·복제, 연결선 상태, 접근성 | 선택 노드만 새 소재용 프리셋으로 저장한 뒤 다른 프로젝트에서 되살린다. 원작 대사·자산·키가 전송되지 않고 필요한 입력 자리가 표시된다. 실행 중인 입력선과 선택 노드의 직접 연결선은 정의한 재생 상한을 공유한다. 320px 화면·키보드·모션 줄이기에서도 상태를 알 수 있다. |

후속 품질 검증에는 사용권이 확인된 단독 인물 사진, 다인 사진, 얼굴·전신이 섞인 시트, 강한 역광 사진을 사용한다. 동일 원본·편집 지시로 **대상 인물 반영, 얼굴·의상 보존, 비대상 변화, 조명 일치, 실제 출력 크기, 호출 횟수**를 기록한다. 옵션 전달과 로컬 분할은 모의 공급사·고정 이미지로 검증하고, 모델별 실제 편집 품질과 비용은 승인된 별도 실험에서 평가한다.
