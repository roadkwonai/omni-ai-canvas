## 1. 시작하기·기획·캔버스

### 사용 가이드 1~3부 기능 조사

파일 약칭: `GD`=GuideDocument.tsx, `ST`=Studio.tsx, `CB`=CanvasBoard.tsx, `PSD`=ProjectStartDialog.tsx, `PL`=ProjectLibrary.tsx, `SPS`=StylePresetStudio.tsx, `WA`=WorkspaceAgent.tsx, `AA`=AgentAttachments.tsx, `af`=lib/attachment-files.ts, `as`=lib/attachment-store.ts. 저장소 루트 기준이고 컴포넌트는 components/ 아래입니다.

#### 1. guide-first

1. **여는 방법**
   - 상단 프로젝트 이름 버튼 → "프로젝트 관리" → 예제 "열기" (PL:170~, 220)
   - "새 프로젝트"는 이 창 안에 있음 (PL:190)
   - 프로젝트가 없으면 "새 프로젝트 시작" (ST:3140)
2. **항목**
   - 예제 "마지막 상영"은 목록에 없으면 서버가 자동 생성 (app/api/projects/route.ts:8~18)
   - 작업실 탭: "대화/제작/노드/지침/기록" (workroom-guide-content.ts:9~99). 기본 시작 탭은 대화 (lib/workspace-preferences.ts:9~13)
   - "화면에서 기능 설명 보기" / "설명 모드 종료" (UserGuide.tsx:69, ST:3436)
3. **한도**: 프로젝트 이름 120자 (PSD:88)
4. **막힘**
   - 작업실 로드 실패: "작업실을 불러오지 못했습니다." + "다시 불러오기" (ST:3136~3139)
   - 저장 상태 문구: "저장됨/저장 대기/저장 중/저장 실패/저장 충돌" (ST:2611~2615)
   - 오류 처리 버튼: "다시 저장", "내 작업 내보내기", "저장본 불러오기" (ST:4682~4705)
   - 프로젝트 전환 전에 저장이 실패하면 "현재 작업을 저장한 뒤 프로젝트를 전환해 주세요." (ST:1302)
5. **가이드 차이**
   - GD:204는 새 프로젝트의 위치(프로젝트 관리 안)와 기본값 "무형식으로 시작"(PSD:30)을 말하지 않음
   - 작업실 헤더의 "가이드"와 "탭 사용법"(ST:3410, 3443)이 빠짐
6. **그림**: 화면 구조(상단·왼쪽·캔버스·작업실 5탭), 저장 상태 변화

   - 자동이어도 씬 수를 바꾼 값은 형식 변경 후 유지됨 (기본값과 같을 때만 새 기본값, PSD:102~108)

#### 3. guide-projects

1. **여는 방법**
   - 상단 프로젝트 이름. 탭은 "작업 중 / 보관함 / 휴지통" (PL:25)
   - 설정: 목록의 "설정", 대화 탭의 "설정" (WA:150)
2. **항목** (PL:190~230)
   - 검색, 카테고리, 태그 필터. 최근 활동순
   - 작업 중: "열기, 설정, 복제, 보관, 삭제". 보관함: "설정, 복제, 복구, 삭제"(열기 없음). 휴지통: "복구"만
   - 설정 창: 프로젝트 이름, 제작 형식 변경, 카테고리(1개), 태그, 복제/보관/삭제, "설정 저장"
   - 설정 창의 보관·삭제는 확인 후 실행. 목록의 "보관"은 확인 없이 바로 실행 (PL:228)
   - 분류 창: "카테고리·태그 전체 관리". "일괄 이름 변경", "전체에서 삭제". "보관함과 휴지통에 있는 프로젝트에도 적용됩니다." (ProjectClassificationsDialog.tsx:84~148)
3. **한도**: 태그 20개 (PL:144), 카테고리 이름 60자, 태그 이름 40자 (ProjectClassificationsDialog.tsx:41), 복제본 이름은 "… 복사본" (app/api/projects/[id]/route.ts:106)
4. **막힘**
   - "이미 선택한 태그입니다.", "태그는 최대 20개까지 선택할 수 있습니다.", "이미 등록된 이름입니다."
   - "프로젝트가 변경되었습니다. 목록을 새로고침해 주세요." (route.ts:105), "프로젝트나 분류가 변경됐습니다…" (ST:1423)
5. **가이드 차이**
   - 내용은 대체로 일치
   - 완전 삭제(휴지통 비우기)가 화면에 없음
   - 보관함 프로젝트는 복구해야 열 수 있음
   - 새 카테고리·태그는 설정 창에서 직접 입력하지 못하고 공용 분류에 먼저 등록해야 함
6. **그림**: 상태 전이(작업 중 ↔ 보관함, → 휴지통 → 복구), 공용 분류와 프로젝트의 관계

   - 계정 미연결·잘못된 씬 수·첨부 처리 중에는 요청 버튼이 꺼짐 (ST:2684~2694)
5. **가이드 차이**
   - 노드 선택을 풀어야 기획 방식이 보인다는 점이 빠짐
   - 기획 방식 3종의 차이와 무료 배치 버튼이 빠짐
   - 새 제작안·자유 구성 요청에는 보드 전체 노드의 제목·본문이 함께 전달됨(연출 확인용으로 쓰인 노드 제외, 미디어는 제외; run-input.ts:183~191)
   - 씬 수가 자동이고 시나리오가 있으면 요청문 없이도 요청 가능 (ST:536~542)
   - 작품 형식을 바꾸면 스타일 프리셋이 해제됨 (DirectorControls.tsx:74)
   - 흐름 그림(GD:273~279)의 "샷 기획 → 대본과 자료"는 실제 보드 순서(기획 → 시나리오 → 씬 → 대본 → 샷)와 다름
   - `[VO]`/`[OS]` 설명은 docs/user-guide.md에만 있음
6. **그림**: 요청 → 기록 → 미리보기 → 적용 흐름, 기획 방식 3종 비교, 검토 제안 상태

#### 6. guide-contest

1. **여는 방법**
   - 제작 도구 → "공모전 기획"(창 제목은 "공모전 준비")
   - 제작 탭 요청란에 공고 HTTPS 주소를 적으면 버튼이 "공모전 요강 확인"으로 바뀜. 옆의 "일반 참고 링크로 첨부"로 우회 가능 (ST:532, 2703, 3822)
   - 스타일 프리셋의 "공모 요강 연결"
2. **항목** (ContestStudio.tsx)
   - "공모전 주소"(필수), "요강 가져오기", 예시 주소 3개, "아이디어와 추가 자료"(선택), "공고 원문 직접 붙여넣기"(선택) → "붙여넣은 원문 정리"
   - 요강 7칸: 공모전 이름, 주제, 영상 규격, 마감, 심사 기준, 출품 방식과 권리, 참가 자격
   - 출처 상태: "실시간 조회 / 직접 입력 / 자동 조회 실패"
   - "공모전 준비 보드 만들기"(5노드·4연결: 공모 요강, 아이디어 스케치, 시나리오, 출품용 대본, 출품 준비 목록), "감독 기획으로 이동"
   - 이후 제작 탭에 "공모전 요강 적용 중", "요강 적용 해제" (ST:3545~3560)
3. **한도**: 항목당 1,800자, 제목 240자, 전달 원문 8,000자, 아이디어 8,000자(lib/contest.ts:52~63, 162), 페이지 본문 1 MiB(lib/contest-source.ts:87)
4. **막힘**
   - "공모전의 https 주소를 입력해 주세요.", "출처 주소를 입력해 주세요."
   - "목록에서 개별 공모전을 선택해 상세 요강을 가져와 주세요."
   - "공개 본문이 비어 있거나 브라우저에서 표시되는 페이지입니다. 공모전 원문을 붙여넣어 주세요."
   - "공개 페이지를 읽지 못했습니다. 로그인 또는 브라우저 확인이 필요할 수 있습니다…"
   - 못 찾은 항목은 "요강에서 확인 필요"
   - "공모전 제목, URL, 요강 분량을 확인해 주세요." (항목이 길 때)
5. **가이드 차이**
   - 원문을 붙여넣어도 출처 HTTPS 주소는 필수 (168~171)
   - 요강을 가져오기 전에 하단 버튼을 누르면 조회만 하고 끝남. 확인 후 다시 눌러야 함 (192~195)
   - 자동 정리는 정규식 발췌로 에이전트를 쓰지 않음
   - "지정 플랫폼", "시간대" 전용 칸은 없음 (GD:290). "마감"과 "참가 자격" 등에 적어야 함
   - 요청란 경로와 "요강 적용 해제"가 빠짐
6. **그림**: 주소 → 요강 확인 → (준비 보드 | 감독 기획) 분기, 출처 상태 3종

#### 7. guide-presets

1. **여는 방법**: 제작 도구 → "제작 프리셋 · 레퍼런스 분석"(창 제목 "영상 스타일 프리셋"). 도구함 제작 키트, 대화 탭 "제작 프리셋", 제작 탭 "제작 프리셋 선택"
2. **항목** (SPS)

   - 제작 형식 10개(기본 AI 인플루언서), 씬 수 1~6, 프리셋 이름, 영상 콘셉트, 연출 기법 18개
   - 레퍼런스: "영상 파일 추가", "YouTube 영상 추가", "프로젝트 영상 추가", "상세 보기", "제거". 2편 이상이면 "영상별 측정값" 표
   - "레퍼런스 분석", "아이디어로 추천받기", "이 프로젝트의 이전 제안", "제안을 편집기에 반영"
   - 컷별 분석(ReferenceCutReview.tsx): 컷 재생, "편집점 직접 보정하기" → "보정한 컷으로 표본 준비", "컷 구간을 골라 자세히 분석하기" → "구간 표본 준비"

   - 스타일 9칸: 전개 방식, 편집 리듬, 구도, 카메라, 감정 연기, 필름·조명, 자막 스타일, 화면 구성, 음향
   - "프리셋 저장" / "변경 저장" / "복사본으로 저장", "기본 노드 추가", "감독과 기획하기"
3. **한도**: 8편, 1 GiB, 60분(lib/reference-limits.ts), 구간 24개·마지막 100%, 이름 100·콘셉트 500·스타일 칸 250·메모 1,000자, 컷 표본 96장, 경계 6,000개, 구간 선택 1~96컷, 긴 영상(10분 초과)은 음성 전사 안 함(af:390)
4. **막힘**
   - "영상 파일은 1 GiB 이하여야 합니다.", "레퍼런스는 최대 8개까지 추가할 수 있습니다."
   - "공개 영상을 가져오지 못했습니다. 60분·1 GiB 이하의 MP4 또는 WebM 파일을 첨부해 주세요." (lib/reference-video.ts:189)
   - "역할을 입력하고 끝 비율이 앞 구간보다 크도록 수정해 주세요.", "프리셋 이름과 구간 순서를 확인해 주세요."
   - "화면 전환 후보를 찾지 못했습니다. 구간을 직접 추가해 주세요."
   - "다른 창에서 프리셋이 변경되었거나 삭제되었습니다…"
5. **가이드 차이**
   - 씬 수는 1~6. 프로젝트의 1~12와 다름. 감독에서 7 이상을 정하고 열면 목록에 해당 값이 없음 (376~379, 874)
   - 제작 형식을 바꾸면 이름·콘셉트·구간·스타일이 모두 초기화됨 (458~468)

   - 화면 글자 인식은 macOS, 전사는 WHISPER_MODEL_PATH 설정 시에만 (af:31, 59)
   - 스타일 프리셋(연출)과 보드 프리셋(노드 구조)의 차이가 설명되지 않음
6. **그림**: 구간 비율 막대(0~100%), 레퍼런스 → 표본 → 분석 → 편집 → 저장 흐름, 두 프리셋 비교

#### 9. guide-attachments

1. **여는 방법**: 제작 탭 요청란 위 첨부 영역, 대화 탭 "자료 첨부"를 펼침
2. **항목**
   - "파일 첨부", "공개 HTTPS 링크" + "추가", "내용 확인", 제거 (AA:298~390)
   - 형식: PNG·JPG·WebP, MP4·WebM, PDF, DOCX, PPTX, MD·TXT·SRT·CSV·JSON
   - 이미지·영상 생성 화면은 축소형: "파일 첨부", "캔버스 참조", "@ 노드 참조", "디렉터 스튜디오" (AA:240~253)

3. **한도**
   - 8개, 파일당 64 MiB, 일반 첨부 영상 2시간, 대표 프레임 3장(10·50·90%), 추출 글 12,000자 (af:14, 247, 289)
   - 요청 합계: 파일 64 MiB, 전달 미디어 12개, 참조 데이터 120,000자 (as 하단)
4. **막힘**
   - "첨부 자료는 최대 8개입니다.", "첨부 파일은 64 MiB 이하여야 합니다.", "공개 HTTPS 주소를 입력해 주세요."
   - "공개 본문을 읽지 못했습니다. 내용을 직접 입력해 주세요."
   - "텍스트 파일은 UTF-8 인코딩이어야 합니다."
   - "PDF 텍스트를 읽지 못했습니다. pdftotext 설치와 파일 상태를 확인하세요."
   - "선택한 서비스는 첨부 이미지를 읽지 못합니다. 내용을 글로 설명하거나 이미지를 읽는 서비스를 선택해 주세요."
   - "첨부 자료의 크기 또는 개수 한도를 초과했습니다."
   - "PNG·JPG·WebP 이미지만 첨부할 수 있습니다."
5. **가이드 차이**
   - **이미지 붙여넣기는 제작 탭에서만 동작** (AA:180이 `.agent-panel`만 찾음). 대화 탭은 끌어놓기와 파일 첨부만
   - **이미지·영상 생성 화면에는 링크·문서 첨부가 없음** (AA:82~92)
   - 12,000자 절단, 합계 한도, 필요 프로그램(ffmpeg/ffprobe, pdftotext·pdftoppm, python3)이 빠짐
   - SRT·CSV·JSON 지원이 빠짐
   - YouTube 링크도 일반 링크로는 본문만 읽음. 장면 분석은 프리셋 화면에서
6. **그림**: 자료 종류 × 서비스 전달 방식 비교

## 2. 이미지·연출·인물·영상·모션

조사만 했고 파일은 바꾸지 않았다. 경로는 모두 저장소 루트 기준이며, 줄 번호는 현재 작업 트리 기준이다.

#### 먼저 고칠 곳 (가이드와 실제가 다른 부분)

1. **예상 사용량** (guide-video 3번, user-guide)
   - Kling·Topview에는 "예상 사용량 확인" 버튼이 없다. 버튼은 Higgsfield를 고르거나 이미지 편집 노드일 때만 나온다(components/Studio.tsx:2643-2661).
   - Higgsfield도 참조 파일이 하나라도 있으면 "참조 파일을 업로드하지 않고는 정확한 비용을 확인할 수 없습니다."만 나온다(lib/runner.ts:769-776). 시작 프레임을 넣는 보통의 영상 작업에서는 금액이 나오지 않는다.
   - Codex와 이미지 API는 "이 서비스의 예상 비용은 확인할 수 없습니다."로 나온다(runner.ts:750-757).
2. **편집 노드 생성** (guide-image 첫 문단)
   - 도구를 고르면 편집 노드가 생기는 것은 연출 10종, 업스케일, 회전뿐이다.
   - 레이어·주석은 저장할 때 노드가 생긴다. 미리보기·다운로드는 노드를 만들지 않는다(Studio.tsx:1631-1667, 1696-1740).
3. **워크플로우 수** (guide-production-skills): "시네마틱 단편·광고·숏드라마" 3종으로 적혀 있지만 실제는 4종이다. "Higgsfield 패션 광고"가 빠졌다(lib/higgsfield-workflows.ts:12-70).
4. **아이디어 뱅크**: 원문을 이 컴퓨터에 보관해야 열리는 조건이 앱 가이드에 없다(components/DramaIdeaBank.tsx:24-45).
5. **디렉터 스튜디오 169가지**: 합계는 맞다. 다만 고르면 선택 해제와 같은 장르 "일반"과 편집 리듬 "자동"이 포함된다(components/NodeDirectorStudio.tsx:38-39, 207). 초점 거리(18~135mm)는 이 수에 들어가지 않는다.
6. **디렉터 스튜디오를 여는 노드**: "이미지·영상 노드"만이 아니다. 작업실 "제작" 탭의 프롬프트 영역에서는 노드 종류와 관계없이 열린다(Studio.tsx:3716, components/AgentAttachments.tsx:251).
7. **미디어 도구**(user-guide): 노드에 이 이름의 버튼은 없다. 노드를 선택하고 "제작 도구 → 클립 편집"을 열면 나오는 창 제목이 "미디어 도구"다(components/ClipLab.tsx:180).
8. **메뉴 이름과 창 제목이 다르다**

| 메뉴 | 창 제목 |
| --- | --- |
| 업스케일 | 이미지 확대 |
| 감독 도구 | 연출 스튜디오 |
| 클립 편집 | 미디어 도구 |
| 모션그래픽 스튜디오 | 모션그래픽 제작 |

"감독 도구"(이 컴퓨터의 배치도·이미지 조정)와 "디렉터 스튜디오"(노드에 저장하는 촬영 지시)는 다른 기능이다. 노드 추가 메뉴에서 "디렉터 스튜디오"를 검색하면 감독 도구가 나온다(components/CanvasBoard.tsx:807).

- "카메라와 배치": 구도 프리셋 4개. 좌우 회전 ±40°, 상하 ±25°, 초점거리 18~85mm(35), 배우·소품 좌우 ±4m와 깊이 0~10m, 앵글 4, 이동 5, 시선 3, 표정·필름 룩·광원 프리셋 각 4(직접 입력 500·160·160자). 버튼은 "촬영 지시 적용"/"촬영 지시 새 샷 추가", "배치도 가이드 저장".
- "이미지 편집": 네 변 자르기 0~45%, 밝기·대비·채도 0~200%(100), 회전 90° 단위. "편집본을 새 참조로 저장"은 최대 2048px PNG다.

**3. 한도**: 연출 지시 2,000자. 저장은 이 컴퓨터에서 하고 비용이 없다. 샷·씬에 저장한 연출은 **연결된 이미지·영상 요청에도 함께 전달**된다(lib/run-input.ts:27-30, 246-248). 이미지 요청에서는 카메라 이동·시간 표현·편집 리듬을 뺀다.

**4. 막히는 지점**
- 충돌 안내가 10종가량 있다(lib/node-director-direction.ts, directionWarnings). 안내일 뿐이며 적용은 막지 않는다.
- 막는 것은 "연출 지시는 2,000자까지 저장할 수 있습니다." 한 가지다.
- 움직임 줄이기를 켠 컴퓨터에서는 카드가 재생되지 않는다(:227).
- 배치도 저장은 샷 노드를 선택해야 한다.

**5. 없는 내용**: 충돌 안내, 다른 노드로의 전달, 초점 거리 조절, 감독 도구 자체(앱 가이드에 설명이 없음).

**6. 그림**
- 구조: 세 묶음과 항목
- 흐름: 샷에 저장한 지시가 이미지(움직임 제외)와 영상에 전달되는 경로
- 비교: 감독 도구와 디렉터 스튜디오

#### guide-production-skills

**1. 여는 방법**: 제작 도구 또는 제작 키트 → "Higgsfield 제작 워크플로우". 광고 형식은 "현재 형식의 추천"에 나올 수 있다(Studio.tsx:2978-2981). Element는 캐릭터·참조 이미지·참조 영상·음향 큐·키프레임의 노드 탭에 있는 "Higgsfield Element"다(Studio.tsx:4286).

**2. 조작** (components/HiggsfieldWorkflowStudio.tsx)
- 제작 유형 4개와 단계: 시네마틱 단편(기본, 3단계), 제품 광고(3), Higgsfield 패션 광고(5), 연속 숏드라마(6).
- 아이디어/브리프 4,000자, 배역 이름(최대 4명, 각 32자).
- 제작 자료 5개. 기본값: 상태 시트는 켜짐. 목소리는 단편·숏드라마만, 룸투어·대안 앵글은 단편만 켜짐. 엑스트라는 꺼짐.
- 씬별 배역: 등장하지 않음/기본 상태/변형 상태. "블로킹 이미지를 생성 입력으로 사용", "배역 비디오를 동작 입력으로 사용"(끄면 샷에서 확인만).
- 패션 광고: 씬 1~12개 또는 자동(기본 9), 화면비 16:9(기본)/9:16/1:1, 공간 배치 참고(켜짐), 렌즈 전환 계획(켜짐), 씬별 배역.
- "선택한 구성으로 노드 추가". 숏드라마 타임라인은 9:16, 나머지 일반 유형은 16:9.
- Element: "계정 참조 불러오기", Element ID·Voice ID(캐릭터 노드에는 Voice ID 칸 없음)·상태·출처, "노드에 기록", "표식 복사"(`<<<ID>>>`). "새 참조 만들기"는 이름 32자, 종류 인물/장소/소품/자동, 이미지 최대 8장(components/NodeElementPanel.tsx).

**3. 실행**: 노드 배치는 이 컴퓨터에서 하고 생성은 없다. Element 조회·생성은 Higgsfield MCP 계정이며, 생성 전에 확인 창이 나온다.

**4. 막히는 지점**
- "배역은 최대 4명, 이름은 각각 32자까지 입력해 주세요."

**5. 주의**: 새 Element는 캔버스 이미지를 바로 올리지 않는다. Higgsfield에 이미 올린 이미지의 UUID와 주소가 필요하다. 표식 복사는 MCP 프롬프트용이며, 가이드의 "Image Element… 연결"은 자동 전송처럼 읽힐 수 있다.

**6. 그림**

#### guide-video

**1. 여는 방법**: 씬·샷·영상·참조 영상·이미지 노드의 "영상 만들기"(씬은 "이 씬 영상 만들기", 샷은 "이 샷 영상 만들기", 우클릭 메뉴 포함), 씬의 "샷별 영상 만들기", 대화 탭 "씬별 영상 만들기". 이미 연결된 영상 노드가 있으면 새로 만들지 않고 그것을 연다(lib/board-edit.ts:21-34).

**2. 조작**
- "프롬프트와 참조": 파일 첨부(8개), 캔버스 참조, @ 노드 참조, 디렉터 스튜디오, "영상 프롬프트"(12,000자), "연결된 제작 자료 N개"(전송 목록).
- "모델과 출력": "영상 서비스"(저장한 기본값이 없으면 연결된 Higgsfield 우선), "영상 모델", "작업 방식". 작업 방식은 모델에 따라 다르다.
  - Higgsfield: 텍스트로 영상 생성, 이미지로 영상 생성, 이미지·영상 참조, 원본 영상 리메이크/편집, 영상 이어쓰기(lib/higgsfield-models.ts:65-70)
  - Kling: 텍스트로 영상 생성, 이미지·키프레임 영상, 복합 참조 영상(lib/kling.ts:91-93)
  - Topview: 텍스트·이미지·복합 참조 등(lib/topview.ts:18)
- "참조 입력 역할": "자동으로 배정"(기본), 슬롯(시작 프레임·끝 프레임·참조 이미지·참조 영상·참조 음향), "본문만 전달". 슬롯마다 최소·최대 개수가 표시된다(components/MediaModelOptions.tsx:167-215).
- 프로젝트 화면비를 지원하면 자동으로 선택한다(Studio.tsx:643-650). lib/video-options.ts의 고정 길이·해상도는 이 화면의 선택지가 아니라 이전 API 형식이다.
- 실행은 "영상 생성" → 기록 탭 "결과 적용".
- 테이크 스위치: 영상 노드를 연결하고 "이 테이크 채택"을 누른다(Studio.tsx:4295-4334). 화면은 두 개를 안내하지만 목록은 연결된 영상을 모두 표시한다.
- Antigravity 인계는 **이미지 작업만** 된다. "Antigravity 앱 · 이미지 수동 작업"을 고르고 "요청과 참조 복사", "참조 내려받기", "생성한 이미지 첨부"를 쓴다(Studio.tsx:572, 3915-3960).
- 미디어 도구: 프레임 추출, 3×3 콘택트 시트, 오디오 추출, 구간 편집(속도 0.5/0.75/1/1.5/2배, 비율 원본/9:16/16:9 중앙 자르기). 음향 파일은 구간 편집만 된다. "결과 만들기" → "새 노드로 추가".

**3. 한도**: 서비스 크레딧이 든다. Kling·Topview 결과는 64 MiB까지. 미디어 도구는 이 컴퓨터의 ffmpeg를 쓰고, 파일 64 MiB, 구간과 결과 각 2분, 콘택트 시트 0.3초 이상이다(lib/clip-tools.ts).

**4. 막히는 지점**
- 생성 버튼이 꺼지는 이유가 위에 표시된다: "'…'에 필요한 참조를 첨부해 주세요.", "'…'에 연결할 미디어를 먼저 적용해 주세요.", "이 작업에는 미디어 참조가 필요합니다."(lib/media-request.ts)
- "이 모델에서 사용 가능한 작업 방식이 없습니다."
- 미연결: Kling `./node_modules/.bin/kling login`, Higgsfield `./node_modules/.bin/higgsfield auth login`, Topview "Topview 계정 연결". 이어 "연결 상태 새로고침".
- 음향 참조는 Higgsfield 영상에만, 영상 노드에 직접 연결했을 때 전달된다(run-input.ts:239-240).
- "Kling 작업 번호를 확인하지 못했습니다. 재시도 전에 Kling에서 작업 상태를 확인하세요."

**5. 없는 내용**: 작업 방식·슬롯 배정, 연결된 씬·샷 본문이 프롬프트에 포함되는 점, 클립 편집, 기록의 "결과 적용", 로그인 명령.

**6. 그림**
- 흐름: 키프레임 → 작업 방식 → 슬롯 → 요청 → 기록 → 채택
- 비교: 세 서비스의 방식과 예상 사용량 가능 여부
- 구조: 노드 역할과 입력 슬롯

### 3. guide-system

**여는 방법**: 저장 상태는 상단. 실행 기록은 오른쪽 작업실 "기록" 탭. 내보내기는 상단 "내보내기" → "프로젝트 JSON" / "영상 내보내기".

**저장 상태**(`Studio.tsx:149, 2610-2616`)

| 문구 | 들어오는 조건 | 다음 |
|---|---|---|
| "저장됨" | 서버 반영 | 편집·실행 취소 → "저장 대기" |
| "저장 대기" | 편집 | 0.9초 뒤 자동 → "저장 중"(`:1141-1147`) |
| "저장 중" | 요청 전송 | 성공 → "저장됨", 중간에 편집했으면 → "저장 대기" |
| "저장 실패" | 409 외 오류 | "다시 저장" 또는 새 편집 → 재시도 |
| "저장 충돌" | 409, 다른 창·MCP가 먼저 저장 | "내 작업 내보내기"(JSON) 뒤 "저장본 불러오기"(확인 창) → "저장됨" |

- 생성 요청, 견적, 프로젝트 전환 전에 먼저 저장한다. 저장이 실패하면 진행하지 않는다.
- 미저장 상태에서 창을 닫으면 브라우저가 경고한다(`:1148-1154`).
- 저장이 끝난 창에 초점을 돌리면 새 버전을 자동 반영하고 실행 취소 기록을 비운다(`:1155-1181`). 미저장 편집이 있으면 반영하지 않는다.
- 작업실을 못 읽으면 "작업실을 불러오지 못했습니다."와 "다시 불러오기".
- 설정 창도 버전 충돌을 검사한다: "다른 창에서 설정을 변경했습니다. 최신 설정을 다시 불러와 주세요." → "서버 설정 다시 불러오기".

**실행 상태**(`Studio.tsx:4547-4553`)

| 문구 | 전이 |
|---|---|
| "대기 중" | 요청 저장 → 실행기가 가져가면 "생성 중". 실행기가 없으면 "대기 작업 시작"("실행기 시작 중…") |
| "생성 중" | 결과 → "완료", 오류 → "실패". 60분(Road Music 180분) 동안 생존 신호가 없으면 만료 "실패" |
| "완료" | "결과 적용"으로 보드에 반영(자동 적용 아님) |
| "실패" | 오류 문구와 "서비스 작업 번호"를 확인. 같은 기록을 되살리는 재실행 버튼은 없음 |
| 만료 "실패" | 보관된 결과가 도착하면 실제 결과의 "완료"/"실패"로 바뀜(`db.ts` recoverRunOutcome) |

- 만료 문구: "실행기 응답이 만료되어 결과를 확인할 수 없습니다. 제공자에서 결과를 확인한 뒤 다시 실행하세요."(`db.ts:252`)
- 생존 신호는 60초마다 보낸다(`scripts/worker.ts`). 활성 작업이 있으면 기록을 3초마다 갱신하고, 30건씩 읽는다.
- 생성 실행의 취소 버튼은 없다(runs API는 조회·등록·대기 재시작뿐). 로컬 음성과 Blender 렌더는 취소가 있다.
- 같은 요청 번호는 중복 등록되지 않는다.
- 복구: 결과를 `.scene-room/run-outbox`에 먼저 적고 DB에 반영한 뒤 지운다. 서버는 시작할 때와 30초마다 재시도한다. 결과를 받기 전에 실행기가 죽으면 보관할 결과가 없다.
- 실행기는 웹 서버와 별도 프로세스라서 서버를 재시작해도 계속된다.
- 터미널 대안: `npm run worker -- --drain <프로젝트-UUID>`, 상주는 `npm run worker`.
- 적용 안내: 노드가 바뀌었으면 "‘제목’의 현재 내용이 바뀌었을 수 있습니다. 실행 결과를 적용할까요?", "이미 적용한 기획 결과입니다."
- 대화·지침·프리셋·모션 기획·연출 검토 결과에는 "결과 적용"이 없다. 각 화면에서 적용한다.
- 보관 위치: 보드·실행 기록·기본값은 Neon, 미디어는 `.scene-room/media/`. 이사할 때 둘 다 백업한다.

**가이드와 다른 점**: `:522` "대기·진행·완료·실패" → "대기 중·생성 중·완료·실패". 저장 문구 5종과 충돌 버튼 이름, 만료, 취소 불가가 없다. JSON은 노드·연결·자산 참조만 담고 미디어 파일을 담지 않는다(`ExportMenu.tsx:135`).

**그림**: 상태도 2개(저장 5, 실행 4+만료), 흐름(결과 복구: 실행기 → 로컬 보관 → Neon), 구조(무엇이 어디에 저장되나).
