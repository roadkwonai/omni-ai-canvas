# 로컬 모션그래픽 레시피

## 제작 흐름

1. 캔버스의 **제작 도구 → 모션 숏 렌더**에서 빈 장면을 만들거나 대본·씬 문구를 가져온다. 활성 제작 프리셋이 있으면 필요한 구간을 고른 뒤 장면 길이로 반영할 수 있다.
2. 장면마다 디자인과 문구를 고르고 보조 문구·수치·프로젝트 이미지가 필요한 장면에는 값을 입력한다. 화면비, 색, 위치와 진입 속도는 작품 단위로 정한다.
3. **모션그래픽 만들기**를 누르면 각 장면이 로컬에서 순서대로 렌더되고 MP4 한 개로 합쳐진다. 결과를 재생해 확인한 뒤 영상 노드로 추가한다.
4. 영상 노드의 **모션 숏 다시 편집**에서 저장된 장면 명세를 불러와 변경하고 새 테이크를 만든다. 음악·효과음은 기존 타임라인에서 별도 배치한다.

## 장면별 디자인

| 선택 항목 | 입력 | 실제 결과 | 연구 자료와의 연결 |
| --- | --- | --- | --- |
| 키네틱 타이포 | 제목·보조 문구 | 텍스트 진입, 강조선과 장면 전환 | bang-motion의 정보 계층과 텍스트 움직임 |
| 숫자와 진행 차트 | 제목·0~100 수치·보조 문구 | 숫자가 0에서 목표값으로 증가하며 진행 막대가 함께 확장 | bang-motion과 animate의 시간에 따른 레이어 값 |
| 단계 설명 | 제목·슬래시로 구분한 최대 3단계 | 순서에 따라 번호와 단계가 하나씩 등장 | bang-motion의 단계적 정보 등장 |
| 카드 스토리 | 제목·보조 문구 | 겹친 도형 카드와 시각 요소 진입 | 카드형 정보 구성과 별도 그래픽 레이어 |
| 이미지 깊이 연출 | 현재 프로젝트의 이미지 노드·문구 | 배경 이미지 확대와 전경 테두리·텍스트가 서로 다른 속도로 움직임 | animated-shorts의 화면 깊이 아이디어 |
| 캐릭터 컷아웃 | 투명 인물 이미지·선택적 배경 이미지·대사 | 인물의 미세한 크기·위치 변화와 말풍선, 별도로 움직이는 배경을 합성 | animated-shorts의 인물과 배경 분리, AI City Builders의 캐릭터 컷아웃 |

사용자가 선택한 이미지의 URL은 프로젝트 노드와 대조한다. 렌더 시에는 로컬 이미지 파일을 읽고 외부 생성 서비스를 호출하지 않는다. 이미지는 이미지 레이어와 전경 오버레이를 결합한다. 카메라 궤도와 3D 모델 조작은 후속 설계다.

캐릭터는 투명 PNG를 선택하면 배경과 자연스럽게 합성된다. 캐릭터가 들어오고 미세하게 커졌다 작아지며 움직이는 동안 말풍선과 배경은 별개 레이어로 유지된다. [3초 컷아웃 예제](http://127.0.0.1:5050/api/assets/971ff489-2c8c-45f7-81af-a029e8cd6902.mp4)에서 샘플 그림과 프로젝트의 샘플 배경을 확인할 수 있다. 표정·입 모양·관절을 따로 조작하는 캐릭터 리깅은 후속 과제다.

텍스트·그래픽·배경을 별도 레이어로 만들고 텍스트는 약간 늦게 등장한다. 숫자와 단계의 중간 프레임은 고정된 시간 기준으로 작성한다. 배경에 사용자가 지정한 이미지가 있으면 이미지 레이어만 천천히 확대된다. 이징은 부드러운 진입과 빠른 진입 두 가지를 제공한다. 영상 노드는 실제 입력 명세를 저장하므로 같은 설정을 다시 열어 수정할 수 있다.

## 긴 영상과 리소스

장면은 최대 48개, 각 장면은 1~30초, 작품 전체는 최대 600초다. 렌더는 장면별로 임시 MP4를 만든 뒤 순서대로 합친다. 완료 결과가 64 MiB를 넘거나 출력 길이가 요청과 다르면 오류를 반환한다. 화면에는 작업 중 상태가 표시된다. 기존 화면에서 결과 MP4를 재생할 수 있다.

장면별 재시도·중간 결과 복원, 정교한 다중 트랙 타임라인, 임의 폰트 선택, 성우·자막의 단어 단위 동기화, 2D 캐릭터 리깅과 3D 장면 렌더는 후속 과제다. 로컬 렌더는 한글 시스템 글꼴을 사용하며 브라우저의 자체 호스팅 Pretendard와 동일한 폰트가 지정된 결과까지 확인한 것은 아니다.

## FFmpeg 버전

모션 숏·타임라인·렌즈 전환·미디어 도구의 로컬 렌더는 2026-11-24에 FFmpeg 8.1.2와 9.1에서 확인했다. 렌즈 전환과 윤곽 추적은 `-fps_mode`를 쓰므로 5.1 이상이 필요하며, 4.4에서는 이 기능만 실행되지 않는다.

FFmpeg 9.1은 그래프 설정 뒤 프레임 크기가 바뀌면 `fade`처럼 크기 변화를 지원하지 않는 필터에서 오류(`Frame size or format changed without filter graph reinitialization`)를 낸다. 9.0까지는 이 검사가 없었다. 캐릭터 컷아웃은 투명도 페이드를 먼저 적용하고 `scale=...:eval=frame`을 `overlay` 바로 앞에 둔다. 프레임마다 크기가 바뀌는 필터를 새로 넣을 때는 다음 필터가 크기 변화를 받는지 확인한다. `overlay`·`scale`은 받고 `fade`·`pad`(기본값)·`xfade`·`zoompan`·`concat`은 받지 않는다.

## 실측 예제

Omni AI Canvas의 로컬 저장소에서 보존한 [3분 9초 예제](http://127.0.0.1:5050/api/assets/e2191022-d1e2-4d93-8289-d6055260af1d.mp4)는 서점 소재의 일곱 장면을 타이포, 수치, 단계, 카드, 샘플 이미지 깊이 연출로 구성했다. 189.00초, H.264, 1280×720, 30fps, 828,082바이트다. 측정 환경에서 로컬 렌더와 결합은 13.56초였다. 기기와 선택한 이미지·영상 설정에 따라 시간이 달라진다.

27.4초와 28.5초의 수치가 26%에서 74%로 증가하고, 54.3초와 55.5초에서 첫 번째 단계 하나가 세 단계로 늘어나는 화면을 각각 확인했다. 음향은 포함하지 않았다. 45초 초과·여러 디자인·이미지 입력·이전 명세 호환 및 잘못된 입력은 회귀 테스트에서 검사했다.

설치한 프로젝트 스킬과 조사한 라이선스·영상 타임코드는 [모션그래픽 기술 검토](motion-skills-research.md)에 기록했다. Omni AI Canvas 구현은 공개된 제작 개념을 참고한 독립 구현이며 원본 프로젝트별 엔진·에셋 전체를 포함하지 않는다.
