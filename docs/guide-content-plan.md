# 사용 가이드 보강 계획

작성일 2026-11-24. 기준은 v0.1.1(`5fce279`)과 커밋하지 않은 가이드 화면 개편이다. 작업 1~5를 마쳤다. 계획과 다르게 한 것은 아래에 적었다.

- 설치 목록, 참조 역할, 증상별 진단, 카드 부분 이름은 도식 대신 표와 번호를 붙인 실제 화면으로 설명했다.
- 프리셋 구간 도표는 기본값이 비어 있어 만들지 않았다. 디렉터 항목은 크기 비교가 쉬운 막대로 그렸다.
- 첫 10분 인포그래픽은 실제 화면과 번호 목록으로, 학습 사진 예시는 표로 바꿨다. 생성 이미지는 11점이다.
- 음성 고르기와 외부 에이전트 흐름은 Archify로 그렸다. 도식·도표는 신규 25개, 기존 4개를 쓴다.

> **실행할 때:** 작업마다 확인란(`- [ ]`)을 갱신한다. 하위 에이전트로 나누면 superpowers:subagent-driven-development, 한 세션에서 이어서 하면 superpowers:executing-plans를 쓴다.

**목표:** 처음 온 사람이 가이드만 보고 기능을 열고, 설정을 고르고, 막혔을 때 스스로 풀 수 있게 한다.

**방식:** 장마다 같은 틀(여는 방법, 순서, 설정 표, 한도와 비용, 막힐 때)을 쓴다. 실제 화면을 먼저 쓰고, 화면에 없는 흐름·상태·구조만 도식으로 그린다. 숫자와 파일은 코드와 대조하는 테스트로 지킨다.

**도구:** Next.js 16, React, SVG·WebP, Archify, Diagram Design, ZTD Charts, Codex `image_gen`(ChatGPT 구독), Ego Browser, node:test.

## 1. 지금 상태

| 항목 | 지금 | 목표 |
| --- | --- | --- |

| 글 분량 | 약 12,000자 | 약 52,000자 |

| 한도·오류 안내 | 일부 장의 문장 | 장마다 표와 펼침 목록, 문제 해결 한 장 |

부족한 이유는 분량만이 아니다. 조사에서 다음 네 가지가 되풀이됐다.

1. 기능을 여는 곳이 적히지 않거나, 메뉴 이름과 창 제목이 다르다는 안내가 없다.
2. 설정의 기본값과 범위가 없다. 사용자가 무엇을 바꿀 수 있는지 알 수 없다.
3. 비용이 드는 곳, 이 컴퓨터에서 처리하는 곳의 구분이 장마다 다르다.
4. 버튼이 꺼지거나 오류가 나올 때 무엇을 해야 하는지 없다.

조사 원문은 [사용 가이드 기능 조사](guide-feature-audit.md)에 장별로 있다(여는 방법, 설정과 기본값, 한도, 화면 문구, 그림 후보). 코드와 문서를 읽어 진행했다. 아래 오류 목록에서 **확인**은 이 계획을 쓰면서 코드로 다시 대조한 항목, **대조 필요**는 작업 1에서 고치기 전에 대조할 항목이다. 화면을 실제로 눌러 보는 확인은 장을 쓸 때 한다.

## 3. 장 공통 틀

장마다 아래 순서를 따르고, 해당 내용이 없으면 칸을 만들지 않는다.

1. **한 문장 소개:** 이 장에서 무엇을 할 수 있는지.
2. **여는 방법:** `제작 도구 › 타임라인`처럼 경로로 적는다. 메뉴와 창 제목이 다르면 둘 다 적는다.
3. **시작하기 전에:** 필요한 노드, 계정, 설치 프로그램.
4. **순서:** 번호 목록 3~7단계. 화면에 보이는 버튼 이름을 그대로 쓴다.
5. **설정 표:** 이름, 고를 수 있는 값, 기본값, 쓰임.
6. **한도와 비용:** 실행 위치(이 컴퓨터, 구독, 크레딧, API)를 같은 네 낱말로 표시한다.
7. **막힐 때:** 화면 문구와 해결. 펼침 목록으로 둔다.
8. **이어서 보기:** 다음 장 링크 1~3개.

글은 합니다체, 그림 속 글은 해요체를 쓴다. 제품 화면의 이름은 바꾸지 않는다.

### 그림을 고르는 기준

| 보여 줄 것 | 방법 | 쓰지 않을 때 |
| --- | --- | --- |
| 버튼과 창의 위치 | 실제 화면 + 번호 표시(번호는 HTML) | 글 한 문장으로 찾을 수 있을 때 |
| 구조, 갈라지는 흐름, 상태 변화 | Archify | 단계가 일직선이고 5개 이하일 때(번호 목록) |
| 사용 순서, 부분 이름, 기능 설명 | Diagram Design | 화면에 번호를 붙이는 것으로 충분할 때 |
| 수량 비교 | ZTD Charts. 코드나 측정에서 나온 값만 | 값이 2개 이하일 때 |
| 조건·설정 비교 | HTML 표. 검색되고 320px에서 읽힌다 | 그림으로 만들지 않는다 |
| 결과의 차이 | 실제 생성 결과 전후 | 장식용 생성 이미지는 넣지 않는다 |

- 생성 이미지 안에는 글자를 넣지 않는다. 설명은 캡션에 쓴다.
- 3D 렌더처럼 보이는 예시는 쓰지 않는다. Blender 장의 실제 화면은 예외다.
- CineGuide 화면(`compose.jpg`, `moves.jpg`)은 쓰지 않는다. 계정 이름, 잔여 크레딧, 다른 프로젝트 이름, 특정 공모전 이름이 보이는 화면은 다시 찍는다.
- 도식은 넓은 화면과 좁은 화면(320px) 두 벌을 만들고 같은 순서로 읽히게 한다.

## 6. 화면과 파일 구조

지금 `GuideDocument.tsx`는 617줄이다. 글이 네 배가 되면 한 파일로 고치기 어려우므로 묶음별로 나눈다.

| 파일 | 맡는 일 |
| --- | --- |
| `components/guide/contents.ts` | 묶음·장 목록, 시작 카드, 그림 크기. React를 쓰지 않아 테스트에서 읽는다 |
| `components/guide/parts.tsx` | `Group`, `Section`, `Path`, `Figure`, `Screen`, `Results`, `Table`, `Trouble`, `Related` |
| `components/guide/{start,plan,board,media,finish,help}.tsx` | 묶음별 본문. 각각 `export default function` 하나 |
| `components/GuideDocument.tsx` | 검색, 목차, 배치만 남긴다 |
| `components/guide.css` | 표, 번호 표시, 펼침 목록, 전후 비교 추가 |
| `tests/guide.test.ts` | 장 주소, 그림 파일, 숫자 대조 |
| `docs/diagrams/guide/*.json·html` | 새 도식의 편집 원본 |
| `docs/diagrams/guide/build.mjs` | 원본에서 `public/guide/*.svg`를 다시 만든다 |

공용 부품의 모양을 다음으로 정한다.

```ts
Path({ steps: string[]; title?: string })                 // 여는 방법. title은 메뉴와 다른 창 제목
Screen({ file: ScreenId; alt: string; marks?: { x: number; y: number; label: string }[] }) // x, y는 % 
Results({ label: string; items: { file: ScreenId; name: string; note: string }[] })
Table({ label: string; head: string[]; rows: ReactNode[][] })
Trouble({ items: [message: string, action: ReactNode][] }) // details/summary. 검색에 걸리면 펼친다
Related({ ids: ChapterId[] })
```

- `Table`은 좁은 화면에서 표 대신 이름·값 묶음으로 보여 준다.
- 그림은 크기를 적고 `loading="lazy"`로 바꾼다(지금은 `eager`). 장으로 바로 이동할 때 위치가 밀리지 않는지 확인한다.
- 정적 랜딩 빌드(`scripts/build-pages.mjs`)는 `director-showcase.ts`에 적힌 예시만 복사한다. 가이드가 쓰는 예시도 복사 목록에 넣는다.
- `docs/user-guide.md`에는 같은 글을 두 번 쓰지 않는다. 오류를 고치고 새 장의 요약과 앱 가이드 주소만 넣는다.

### 공통 조건

- 랜딩과 제작실이 연결하는 주소 10개를 유지한다: `guide-formats`, `guide-models`, `guide-production-skills`, `guide-projects`, `guide-settings`, `guide-image`, `guide-timeline`, `guide-contest`, `guide-presets`, `guide-blender`.
- 버튼·창 이름은 코드의 문구를 그대로 쓴다. 문구는 `제작 도구 → …`가 아니라 `Path`로 쓴다.
- 요금 금액은 적지 않는다. 과금 방식과 확인할 곳만 적는다.
- 새 그림은 `docs/diagrams/README.md`에 원본·쓰는 곳·검증 범위를 적는다.
- 가이드 그림 전체는 4MB 이하(지금 348KB).

### 검토할 때 먼저 볼 곳

1. 검색어가 펼침 목록 안에만 있을 때: 그 장이 걸리고 목록이 펼쳐져야 한다.
2. `/guide#guide-export`처럼 아래쪽 장으로 바로 들어올 때: 그림이 늦게 불려도 그 장이 화면에 있어야 한다.
3. 320px에서 설정 표와 긴 오류 문구: 가로 스크롤 없이 읽혀야 한다.
4. 제작실 안의 가이드 창과 `/guide` 페이지: 같은 내용이며 창 안의 링크가 창을 벗어나지 않아야 한다.
5. GitHub Pages(`/omni-ai-canvas` 아래): 새 그림 주소가 모두 열려야 한다.

## 9. 위험과 정할 것

| 위험 | 대응 |
| --- | --- |
| 화면이 바뀌면 글과 그림이 낡는다 | 숫자는 테스트로 지키고, 화면은 촬영 스크립트를 남겨 다시 찍는다 |
| Archify의 좁은 화면판이 읽기 어렵다 | 파일럿에서 방법을 정하고 나서 나머지를 만든다 |
| 생성 결과가 연출 설정과 다르다 | 다시 만들기는 한 번. 그래도 다르면 화면 설명만 쓴다 |
| 글이 길어져 찾기 어렵다 | 설정 표와 막힐 때는 펼침으로 두고 검색에 걸리게 한다 |
| ChatGPT 구독 사용량 | 생성 이미지 12점에 다시 만들기를 더해 최대 24회로 제한한다 |

정할 것은 세 가지이며, 답이 없으면 권장안으로 진행한다.

1. **범위:** 33장 전체(권장) 또는 오류 정정과 핵심 12장까지.
2. **생성 이미지:** 구독 사용량으로 12점을 만든다(권장) 또는 기존 예제 그림만 쓴다.
3. **실행 방식:** 작업 1~3은 한 세션에서 이어서 하고, 작업 4~5는 묶음별 하위 에이전트로 나눈 뒤 작업 6에서 함께 검수한다(권장).

### 가이드 밖에서 발견한 것

가이드 작업에 포함하지 않는다.

- Tripo의 “리깅 제출”과 “동작 적용 제출”에 확인 창이 없다. 파일 등록에는 있다.
- 스타일 프리셋의 씬 수는 1~6, 프로젝트의 씬 수는 1~12다. 7 이상인 프로젝트에서 프리셋을 열었을 때의 화면은 확인하지 않았다.
- 생성 실행을 취소하는 버튼이 없다. 설계 의도인지 확인이 필요하다.
