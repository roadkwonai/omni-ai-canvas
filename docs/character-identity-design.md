# 캐릭터 시트의 외형과 목소리

## 작업 흐름과 인수 기준

| 범위 | 제작자 작업 | 완료 조건 |
| --- | --- | --- |
| C3·C8 캐릭터 등록 | 캐릭터 시트에서 기존 Soul을 고르거나 사용 권한이 있는 사진으로 학습을 시작한다. 별도로 계정의 목소리를 등록한다. | Soul ID와 목소리 ID·유형을 따로 저장한다. 시트를 다시 열어 학습 상태를 확인하고 각 연결을 변경할 수 있다. |
| C4·C6·C7 외형 재사용 | 준비된 Soul로 캐릭터 기준 이미지를 만들고 검토한 뒤 시트에 적용한다. 시트를 영상에 인물 외형으로 연결한다. | Soul 이미지 요청은 호환 모델에 Soul ID를 전달한다. 영상은 모델이 지원하는 이미지 입력에 채택 이미지 또는 이를 사용해 만든 시작 프레임을 전달한다. |
| C4·C8·C9 목소리 재사용 | 음향 큐에서 화자를 고르고 발화할 대사를 확인한 뒤 음성을 생성한다. | 실행 입력은 시트의 목소리 ID와 유형을 고정한다. 결과를 같은 큐에 적용하면 기존 타임라인 배치에서 사용할 수 있다. 지원하는 영상 방식에서는 적용된 큐의 오디오도 참조할 수 있다. |

## 저장과 실행

기존 프로젝트 그래프의 캐릭터 노드에 `characterIdentity`를 추가한다. 구형 시트도 열 수 있으며 기존 Element 메모는 보존한다. 외형과 목소리를 연결하거나 해제할 때 프로젝트의 버전 검사를 사용한다. 보드 프리셋은 구조만 보관한다.

캐릭터에서 음향 큐 또는 미디어 노드로 향하는 입력 연결은 `identity` 역할을 사용한다. 감독안의 `[VO]` 화자 이름이 배역 한 명과 일치하면 큐를 만들 때 연결한다. 여러 배역이 연결된 음향 큐는 화자를 한 명으로 지정해야 한다. 가이드 연결은 공급사 실행에서 제외한다.

캐릭터 생성은 기존 로컬 CLI 로그인과 프로젝트의 미디어 저장 경로를 이용한다. 사진 5~20장을 전송하기 전에 권한과 계정 사용량을 표시한다. 준비 중인 Soul ID를 프로젝트에 저장해 화면을 다시 열어도 상태를 조회할 수 있다. 발급 응답을 받지 못하면 계정의 Soul 목록에서 기존 학습을 확인한 뒤 다시 요청한다.

개인 목소리는 작업실에서 OAuth로 연결한 MCP가 등록·업로드·확인 도구를 제공할 때 MP3 또는 WAV 샘플로 등록한다. 등록 요청 전에 파일 전송과 목소리 사용 권한을 확인한다. 준비 여부는 현재 CLI 계정의 목소리 상세 조회 또는 MCP 결과에서 확인한다. 등록 도구가 없는 계정은 Higgsfield Audio의 **Create custom voice**에서 생성하고 작업실의 목록에서 해당 목소리를 선택할 수 있다. VO는 CLI 계정에서 사용할 수 있는 목소리 ID와 유형을 검사한 뒤 발화 대사만 전달한다. 기존 Road Music 음악·효과음과 직접 녹음도 사용할 수 있다.

## 구현 순서와 검증

1. 그래프 저장과 실행 시점의 외형·목소리 스냅샷을 추가한다.
2. 시트에서 등록·학습 상태·기준 이미지 제작과 화자 연결을 제공한다.
3. CLI 입력, 참조 슬롯, 결과 적용을 검증한다. 공급사 작업은 모의 응답과 차감 없는 조회로 검증한다.
4. `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`와 작업실 반응형 화면을 확인한다.
